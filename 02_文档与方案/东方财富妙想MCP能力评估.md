# 东方财富妙想 MCP 能力评估

> 初次调研：2026-11-13；安装复验：2026-11-15  
> 目标：判断妙想 MCP 是否能支撑广发证券式 Skill，尤其是 `gf-etf-search` 的 ETF 筛选能力  
> 结论先行：**可以做出核心筛选体验，但无法“数据口径完全一致”地完美复刻。**

- 当前 Codex 会话的工具清单不会热加载，重启 Codex 后会出现妙想 MCP 工具

## 2. MCP 工具清单

该 Server 共提供 **1 个 MCP Server / 11 个工具**。所有工具输入都只有一个字符串参数：`query`。

| 工具 | 能力 |
|---|---|
| `mx_ashare_finance_data` | A 股基本资料、行情与技术指标、财务估值、股本股东、公司事件、风险指标 |
| `mx_bond_finance_data` | 债券信息、行情估值、发债主体财务、信用评级、可转债条款 |
| `mx_comprehensive_finance_data` | 跨市场、跨品种、非上市企业等综合查询 |
| `mx_finance_search_news` | 新闻、研报、评级、目标价、行业观点 |
| `mx_finance_search_notice` | 上市公司、基金、债券、交易所公告 |
| `mx_fund_finance_data` | 基金基本资料、净值、收益、持仓、份额、基金经理 |
| `mx_hk_finance_data` | 港股资料、行情、财务、估值、事件 |
| `mx_index_block_finance_data` | 指数、行业、概念、板块行情和估值 |
| `mx_macro_data` | 宏观、行业经济、大宗商品高频和历史数据 |
| `mx_stocks_screener` | 选股、选基、ETF 筛选、榜单和条件排序 |
| `mx_us_finance_data` | 美股资料、行情、财务、估值、事件 |

这 11 个工具是按“数据域”划分的，不是按广发那种“业务 Skill”划分。它们更接近统一的自然语言数据查询入口。

| 能力 | 实测情况 | 判断 |
|---|---|---|
| 近 1 年最大回撤筛选 | 作为筛选条件返回空结果 | 不支持直接筛选 |

| PE 历史百分位小于 20% | 被理解为“PE 小于 20”，返回的是 PE 数值而不是百分位 | 自然语言语义不可靠 |
| ETF 近 5 日净申购金额 | 可返回“区间份额变化”，但不是净申购金额 | 只能近似 |
| ETF 资金异动 | 无专门异动工具，需基于份额变化二次判断 | 只能近似 |
| 龙虎榜 | 结构化工具返回空；新闻搜索只返回相关新闻 | 无结构化龙虎榜 |
| 基金定投计算器 | 无现成计算工具，但能返回日度复权净值 | 可在 Skill 侧自行计算 |
| 多字段一次返回 | 经常只返回用户问题中的一个核心指标 | 需要拆成多次调用 |

### 3.3 典型返回结构

妙想返回的是动态表格：

```json
{
  "data": [
    {
      "columns": ["序号", "代码", "名称", "最新价-2026.11.13", "涨跌幅(%)-2026.11.13"],
      "items": [
        ["1", "159050", "机器人ETF广发", "0.844", "-0.47"]
      ]
    }
  ]
}
```

优点：

- 对自然语言友好
- 可以直接给出表格
- 字段随问题变化，灵活

缺点：

- 列名带日期后缀，不稳定
- `columns/items` 不是强类型对象
- 需要 Skill 自己把表格转成业务字段
- 列数量不可控，单次可能返回大量无关列

## 4. 与广发 `gf-etf-search` 的逐项对照

广发 Skill 的核心筛选参数如下：

| 广发参数 | 妙想 MCP 支持情况 | 结论 |
|---|---|---|
| 搜索代码 / 名称 | 支持 | 可复刻 |
| ETF 类型 | 支持 | 可复刻 |
| 宽基 / 行业赛道 | 支持 | 可复刻 |
| 一级赛道（科技等） | 支持 | 可复刻 |
| T+0 | 支持 | 可复刻 |
| 两融标的 | 支持 | 可复刻 |
| 近 1 周 / 1 月 / 6 月 / 1 年涨跌幅 | 已验证 1 周、1 月、6 月、1 年 | 可复刻 |
| 收益率区间 | 部分支持 | 需模板化验证 |
| 资产规模区间 | 支持 | 可复刻 |
| 排序 | 支持 | 可复刻 |
| 分页 / 条数 | 指定排序后可用；不指定排序时可能返回全量 | 需封装 |
| 实时涨跌幅 | 返回当日最新行情 | 基本可复刻 |
| 最大回撤 | 无直接筛选；可取日度复权净值后本地计算 | 功能可补，但不是原生 |
| 夏普比率 | 无直接筛选；可取日度净值后本地计算 | 功能可补，但公式口径需自定 |
| 估值低位 / 中位 / 高位 | 可取 PE/PB 及历史百分位，但广发的分类口径未知 | 不能保证一致 |
| 指数温度 | 可取指数 PE/PB 历史百分位，但没有“指数温度”字段 | 不能保证一致 |
| ETF 资金异动 | 只能取份额变化，缺少净申购金额和异动模型 | 只能近似 |

## 5. 关键样例：510330 华夏沪深300ETF

广发返回：

- 近 1 年最大回撤：约 `-20.11%`
- 近 1 年夏普：约 `-80.67`
- PE：约 `13.40`
- PE 历史百分位：约 `64.95%`
- PB：约 `1.33`
- PB 历史百分位：约 `18.49%`
- 指数温度：约 `34.14`，分类为 `ord`
- 估值分类：`2`（中位）

妙想返回 / 本地计算：

- 日度复权净值：可返回 242 个交易日
- 本地计算最大回撤：约 `-20.12%`，与广发非常接近
- 本地计算夏普（无风险利率 0）：约 `-0.66`
- 沪深300 3 年 PE 历史百分位：约 `61.04%`
- 沪深300 3 年 PB 历史百分位：约 `38.96%`
- 指数温度：没有原生字段

判断：

- **最大回撤可以通过日度净值二次计算，功能上可复刻。**
- **夏普比率可以计算，但与广发的具体年化、无风险利率、收益率序列和窗口口径未必一致。**
- **PE/PB 数值接近，但历史百分位的窗口和口径不同。**
- **“指数温度”不是妙想原生字段，不能声称完美复刻。**

## 7. 最终判断

### 能否完美复刻？

**不能。**

原因不是妙想没有数据，而是：

1. 妙想的输入是自然语言 `query`，不是广发那种强类型筛选参数；
2. 高级指标不是原生字段，需要 Skill 二次取数和计算；
3. 广发的估值温度、指数温度、夏普等指标口径没有公开，无法保证数值一致；
4. 返回列名和列数动态变化，不满足稳定的工程契约；
5. 多字段查询经常只返回一个核心指标，需要拆成多轮调用。

### 能否做出类似的用户效果？

**可以，而且可以做得比广发更灵活。**

建议把 Skill 设计成四层：

```text
用户自然语言
  -> 意图与参数解析
  -> 妙想 MCP 查询模板
  -> 结果标准化 + 本地指标计算
  -> Final Answer 生成
```

具体分工：

- Skill 负责：意图识别、参数标准化、查询模板、结果清洗、指标计算、风险提示
- 妙想 MCP 负责：原始行情、财务、净值、指数估值、新闻公告
- 前端负责：卡片、图表、候选池、结果导出

建议优先实现：

1. 基础 ETF 筛选
2. ETF 涨跌榜
3. ETF 条件排序
4. 单只 ETF 详情
5. 最大回撤 / 夏普本地计算
6. 估值百分位和指数温度自定义口径
7. 份额变化近似资金异动

## 8. 工程注意事项

- 所有妙想工具都标记为 `destructiveHint=true`、`openWorldHint=true`、`readOnlyHint=false`，接入时需要在产品层增加只读约束和调用确认策略。
- URL 响应可能非常大：日度净值约 1.5 万字符，公告检索约 10 万字符。
- 必须做输出裁剪，不能把完整 MCP 响应直接交给模型。
- API Key 目前按文档写入了 Codex 配置请求头，生产环境建议改为凭证代理或系统密钥库。
- 需要对自然语言查询做回归测试，特别是“区间、百分位、前 N、排序”这些词。
- 当前 `mx_stocks_screener` 在指定排序后能稳定遵守“前 10 只”；不指定排序时可能返回全量。

## 9. 一句话结论

妙想 MCP 足以支撑一个“ETF 筛选助手”的主体框架，但它更像自然语言数据查询底座，而不是广发那种参数确定、结果稳定的 ETF 专用 API。要做到广发式体验，必须在其上再加一层**查询模板、结果归一化和本地指标计算**；要做到数据口径完全一致，则缺少公开公式和原生风险指标，无法保证。
