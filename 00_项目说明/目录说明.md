# 项目目录说明

本项目的目标不是堆叠资料，而是形成一条可复核的证据链：

```text
官方/平台原始资料
→ Skill 包与接口说明
→ 真实调用和测试
→ 与妙想 MCP 的对比
→ 首期产品决策
```

## 目录职责

| 目录 | 作用 | 不用于什么 |
|---|---|---|
| `00_项目说明/` | 研究规范、目录说明、交接审计、术语和方法 | 不放竞品原始包或测试结果 |
| `01_竞品Skills/` | 保存机构原始 ZIP、解压包、官网包、WorkBuddy 包、公开检索证据 | 不放产品结论 |
| `02_文档与方案/` | 对单个机构、单个能力、技术链路做拆解 | 不放未经整理的原始响应 |
| `03_能力矩阵/` | 跨机构横向比较、妙想复刻评估、首期产品决策 | 不把主观分数当成事实 |
| `04_测试结果/` | 输入、原始响应、Final Answer、截图、批量基准 | 不混入生产凭证 |
| `05_手机与登录/` | ADB、手机登录和验证码能力评估 | 不保存验证码和个人通信内容 |
| `99_临时文件/` | 临时网页、下载探测、比较中间文件 | 不作为正式交付证据 |
| `tools/` | 可复用的妙想客户端、批量测试和汇总脚本 | 不保存 API Key |

## 为什么有“公开检索证据”

`01_竞品Skills/公开检索证据/` 保存的是搜索引擎、公开报道、官方页面抓取的原始证据。  
它的作用是为“某机构是否上线过某类 Skill”提供出处，不是最终竞品结论，也不是安装包目录。

正式结论写在 `03_能力矩阵/`，原始包放在各机构目录，测试数据放在 `04_测试结果/`。

## 证据等级

- **A级**：官网、官方 API、官方 ZIP、真实接口响应。
- **B级**：权威媒体或官方公告，但未拿到原始包。
- **C级**：搜索摘要、二手文章、截图，需要后续核验。
