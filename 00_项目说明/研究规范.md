# 项目研究规范

## 1. 目录规则

```text
00_项目说明/        项目规则、索引、术语
01_竞品Skills/
  ├── 广发证券/
  │   ├── packages/          原始 ZIP
  │   ├── extracted/         解压后的技能包
  │   └── installed_snapshot/ 可选安装快照
  ├── 东方财富妙想/
  │   ├── docs/
  │   └── metadata/
  ├── 公开检索证据/              公开检索证据
  └── <其他机构>/
02_文档与方案/       分析文档和方案
03_能力矩阵/         横向比较和产品决策
04_测试结果/
  ├── 广发证券/
  │   ├── raw/               原始 API 返回
  │   └── final_answers/     预期最终回答
  └── 东方财富妙想/
      ├── raw/
      └── final_answers/
05_手机与登录/       ADB、登录、验证码能力
99_临时文件/         临时下载、脚本产物，不属于正式交付
```

## 2. 机构目录规则

每个机构必须有：

- `packages/`：原始安装包
- `extracted/`：解压后的内容
- 如无公开包，可只保留 `notes/` 和证据文件

每个 Skill 的测试必须有：

- 测试输入
- 原始输出
- 错误输出
- 执行时间
- 最终回答样例
- 与妙想的对比结论

## 3. 证据规则

- 官方文档、官方页面优先级最高
- 权威媒体文章作为“已确认”证据
- 搜索摘要、截图和二手文章必须标注“待核验”
- 不把没有官方入口的搜索结果写成已支持
- 不把“页面可访问”误写成“已下载”或“已安装”

## 4. 安全规则

- 不把 API Key 写入文档、Markdown、日志或 Git
- API Key 只放本机受保护位置
- 不批量读取手机短信、通讯录、照片和聊天记录
- 验证码只用于当前目标页面，不保存
- 第三方 ZIP 必须先检查路径穿越和危险命令
- 不直接执行来源不明的安装脚本

## 5. 命名规则

- 机构名使用中文
- Skill 包使用官方名称
- 原始文件使用 `<skill>_<case>.json`
- 最终回答使用 `<skill>_<case>.md`
- 对比报告使用 `<机构A>vs<机构B>_<主题>.md`

## 6. 当前口径

- “已下载”：ZIP 或安装包已在本地
- “已安装”：已复制到 `~/.codex/skills`
- “已实调”：真实调用了 API 并拿到返回
- “可复刻”：最终回答结构和主要字段接近
- “数值一致”：同一时点、同一口径下数值完全相同
## 7. 2026-11-15 补充规则

### 平台 Skill 的三种状态必须分开

- **可检索**：平台搜索页能看见卡片。
- **已安装**：本地出现 `SKILL.md` 和元数据。
- **已实调**：真实调用接口并拿到结果。

不得把“可检索”或“已安装”写成“已实调”。

### 批量测试必须保留采用标记

妙想筛选结果可能包含：

```json
"meta": {
  "screeningResultAdoption": {
    "adopted": "采用/不采用",
    "reason": "..."
  }
}
```

统计时必须区分：

- 协议成功；
- 条件被采用；
- 条件被拒绝；
- 空结果。

协议成功不能等同于业务成功。

### 竞品对照必须保留证据链

每个对照至少保留：

1. 输入问题；
2. 竞品原始响应；
3. 妙想原始响应；
4. 双方 Final Answer；
5. 字段差异；
6. 结论差异；
7. 数据日期与口径。

### 平台结果不是全量

WorkBuddy 搜索页有推荐上限和排序机制。只记录实际可见卡片，不把“搜索页显示 100 条”写成“平台共 100 个 Skill”。
