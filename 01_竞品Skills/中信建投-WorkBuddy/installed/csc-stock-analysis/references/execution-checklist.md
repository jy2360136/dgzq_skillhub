# 执行清单（强制对照，逐步打勾）

> 本文件把 SKILL.md 的 Step 0 → Step 5 流程拆成可勾选清单。**每次执行分析必须按序对照**，全部通过后才能输出报告。流程定义以 SKILL.md 为准，本清单是执行视图。

## Step 0：前期准备（对象门控 + API Key 门控 + 数据源连通性 + 标的确认 + 二次核验）

- [ ] 0.00 **对象门控（先于 0.0）**：未点名个股，且问的是大盘、指数、市场风格、行业比较、板块轮动、入场或资金配置 → 原样返回 SKILL.md 对象门控的固定两句，本次结束，不进入 0.0。已点名个股则通过。想分析个股但名称没说清时，只请用户补充，不查指数、不查板块
- [ ] 0.0 **API Key 门控（0.00 通过后）**：已确认运行环境配置了 `CSC_SKILLHUB_API_KEY`；**未配置 / Key 无效 / 额度耗尽（429、quota exceeded）→ 立即终止本次调用**，原样返回 SKILL.md「API Key 门控」的引导提示并补一句具体原因，**不做任何降级/绕过**。取数调用已带 `X-API-Key`（取 `$CSC_SKILLHUB_API_KEY`，**不写死 Key**）与 `X-Calling-Skill-Id` 两个请求头
- [ ] 0.1 发出最轻量探测查询（如 `查询三一重工600031最新收盘价和涨跌幅`），MCP 正常返回。只有 0.00 通过后才发
- [ ] 0.2 确认标的代码（单股 1 个 / 对比 2-8 个）；用户只给名称时已先搜索确认代码
- [ ] 0.3 按 §八 批2 分三句拉取：①收盘价、涨跌幅、成交额、换手率、量比 ②总市值、流通市值 ③PE、PB、股息率。未打成十指标一句
- [ ] 0.4 **实时行情二次核验**：批2①再发一次，比对最新价/涨跌幅；总市值用最新价×总股本复算，PE/PB 核对③是否为最新交易日。价不一致时第三次取多数；市值或估值对不上再重问对应那一句
- [ ] 盘中数据已标注精确时点；盘后数据两次完全一致

> ⚠️ 0.4 未通过前不得进入 Step 1 之后的数据引用。MCP 报错 → 转 `error-handling.md`。

## Step 1：覆盖范围判定（默认六维 vs 专项裁剪）

- [ ] 已判定任务形态：单股深度 / 多股对比（2-8 只）

- [ ] **已按显式词表判定覆盖集合并记录命中依据**：技术面 → 技术面 + 资金面 + 行业/市场校准；财报/价值面 → 基本面 + 财务面；消息面 → 新闻 + 公告 + 事件；综合 / 未命中 → 六维全覆盖
- [ ] **覆盖集合已记录**（主维度 + 配套数据 + 安全网）
- [ ] **安全网（公告 + 事件，5 条查询）已列入执行计划**——任何模式不可裁剪

## Step 2：按意图收集数据

**通用取数（六维模式全查；专项模式按覆盖集合取数，安全网必跑）**：

- [ ] 2.1 基础行情与估值：最新价、涨跌幅、成交额、换手率、量比、总市值、流通市值、PE(TTM)、PB、股息率
- [ ] 2.2 K线与技术指标：显式日期区间的日K（开高低收+成交量，前复权）→ **技术指标本地算**；「最近 N 日」只作约 30 行回退；翼答技术指标 query 仅本地计算不可用时回退
- [ ] 2.3 财务数据：按 §八 批1 的 1a/1b/1c 拆问（ROE、毛利率、净利率、营收及同比、净利及同比、资产负债率、每股经营现金流、EPS），禁止八指标一句；已标注报告期口径
- [ ] 2.4 估值分位：先按 §八 批3 取 PE(TTM)/PB 及近三年历史分位；没有分位列则用逐日 PE 本地算分位。写入报告时区间用「至」，禁止半角 `~`
- [ ] 2.5 资金流向：照抄批5。①最近30个交易日主力资金流向（主力净流入额、大单净额、涨跌幅）；5日/10日净额和连续流入天数从该序列本地算，不另发查询。②最新融资余额和融资净买入额。①返回过大时才缩到10日
- [ ] 2.6 行业与市场：照抄批7一句（申万一级行业；该行业指数最近10日收盘与涨跌幅；上证、深成、创业板最新行情与上涨下跌家数）。市场广度只用返回的成分股口径上涨家数·下跌家数表。指数实时行情表里的同名字段不用。不要改问「行业板块、概念板块」。合并问没有指数涨跌幅时，再单问收盘点位和涨跌幅
- [ ] 2.7 研报与机构评级（价值/ST 意图强烈建议）：机构评级、最近研报观点（注意大返回体，限时限条数）
- [ ] **2.8 新闻、公告与事件（六维模式必查三项；专项模式：公告 + 事件为安全网必查、新闻按覆盖集合）**
  - [ ] **公告与事件已查**（内部称安全网，不写入报告）：公告 1 条 + 事件四组（E1/E2/E3a/E3b）4 条；命中重大负面清单（立案处罚 / 首亏预减 / 控股股东高质押 / 大额诉讼 / 退市警示 / 核心资产查封）时，在「公告与事件」章写出「已披露重大事项提示」并进风险提示第 4 条；没有应关注事项则该章写「未发现」
  - [ ] 公告或事件取数失败 → 该章写「未获取到数据（原因）」（未静默、未写成"无公告"，报告中不写"安全网未生效"）
  - [ ] 新闻：最近 1 周动态，已逐条核对是否确实涉及本标的，已标注来源与发布时间（**专项模式未查新闻时记 `NOT_COVERED`，不得记 `NA`、不得写"无新闻"**）
  - [ ] 已判别失败类型（A 返回过大→**拆窄重问** / B 表在但为空→记"未发现" / C 全噪声→剔除后为 0 才算缺失 / D 接口真失败→降级）
  - [ ] 若命中 A 类，已按「限定条数 → 缩短时间窗 → 拆单类」重试，未直接记为缺失
  - [ ] 公告：最近 3 个月公司公告，已提取日期/编号与关键事实
  - [ ] 事件四组 query **全部跑完**（E1 业绩预告/快报；E2 回购·增减持·股权激励·解禁·分红；E3a 质押·重组担保·诉讼监管；E3b 高管停复牌·再融资·退市警示），**未自行拼词漏类、未把 E3a/E3b 合并回一句**，也未因行情禁令改写「最近一年」
  - [ ] 写入报告的区间已把数据源里的 `~` / `～` 改成「至」（含 E1 业绩预告的净利润区间与同比幅度）。未照抄 `72.14~81.16`、`+60%~+80%`，避免成对波浪号被渲染成删除线、复制后粘成 `72.1481.16`、`+60%+80%`
  - [ ] 某组最新一条早于近 3 个月时，已按该组补问一次；四组都旧时只补了 E1。补问后仍无近 3 个月记录才写「未发现」，未把上一个自然年直接滤成「未发现」
  - [ ] 11 类逐类扫描完成，命中已记录，未命中写"未发现"
  - [ ] 结构化表"暂无数据"但新闻/公告命中同类事件时，已**并列呈现**（表记"未发现"+新闻侧单列），未互相覆盖
  - [ ] 传闻/预期与公告事实已分栏，未把传闻写成既成事实
  - [ ] 数据不可得项已写"未获取到数据（原因）"，未静默跳过
  - [ ] 真缺失维度已按 `scoring.md` §3 记 **NA**（先完成拆窄重问，**未**跳过重试直接 NA；未用估算值填充），未评分项已在报告中列出
  - [ ] **未覆盖维度已记 `NOT_COVERED`**（措辞"未查询（按用户指定范围）"），**未**与 `NA` 混写、**未**写成"无风险/正常"

**多股对比附加**：

- [ ] 每只股票都执行了同样的查询清单（口径统一：同时间窗/同报告期/同复权方式）

**查询纪律**：

- [ ] 未使用禁用宽问法（新闻未限条数、行业+概念合并问、E1 夹带研报词、E3a/E3b 合并回一句）

  - [ ] 已输出**有效数据覆盖率**与**未评分项**（NA / NOT_APPLICABLE / SAFETY_NET）；专项模式另列 **`NOT_COVERED`**（未查询）清单；覆盖率 <80% 时**未**输出总分

  - [ ] **未出现**评级词（强烈推荐/谨慎推荐/中性/观望/回避）
  - [ ] **未出现**建仓/持股/减仓/观望期、入场条件、**止损位**、**目标位**、执行建议
  - [ ] 关键位只以**支撑位/压力位**呈现（数据源原生字段）
