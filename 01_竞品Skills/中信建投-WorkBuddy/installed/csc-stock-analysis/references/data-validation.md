# 数据核验清单（硬公式版）

> 本文件是 SKILL.md 核心铁律第 3/4/6/9 条的执行细则。**取数完成后、写报告前必须对照本清单核验**；任何一项未通过，先修正再继续，禁止"先发再改"。

---

## 一、实时行情二次核验（强制）

| 核验项 | 检查内容 | 容差 | 修正措施 |
| --- | --- | --- | --- |
| 数据一致性 | 两次查询的最新价/涨跌幅/成交量是否一致 | 盘后须完全一致 | 第三次查询，取多数一致值 |
| 涨跌幅计算 | 涨跌幅 = (最新价 − 昨收) / 昨收 × 100% | 误差 < 0.1% | 复算不符则以行情表原值为准，标注差异 |
| 市值计算 | 总市值 = 最新价 × 总股本 | 误差 < 1% | 复算不符时以当前数据源返回值为准（股本口径可能含限售） |
| 单位一致性 | 成交量（手/万手）、成交额（万元/亿元） | 单位必须显式标注 | 换算后统一为万元/万股 |
| 盘中跳动 | 两次查询价差不等于涨跌幅应有变化 | — | 以第二次为准，报告标注精确时点 |

**盘中特例**：交易时段内两次查询价格自然变化属正常，不视为"不一致"；但 PE/PB/市值与价格的联动关系仍须复算合理。

## 二、表格结构核验（所有输出表格）

| 核验项 | 标准 | 处理 |
| --- | --- | --- |
| 错行错列 | 表头与数据列严格对齐 | 逐列比对，发现错位重新生成 |
| 合计/总计 | 合计 = 各分项之和 | 误差 < 0.01（相对值） |
| 占比之和 | 各分项占比之和 = 100% | 容差 < 0.1%；超出时重算或标注四舍五入说明 |
| 空单元格 | 关键字段不允许空 | 空值标注"数据缺失"，禁止填 0 冒充 |
| 组件归类 | 多组件返回时按组件标题/字段正确归类（翼答无 `api_name` 表名概念） | 张冠李戴直接重做对应部分 |

## 三、财务数据核验公式

| 核验项 | 公式/标准 | 容差 |
| --- | --- | --- |
| 同比增速 | (本期 − 上年同期) / 上年同期 × 100% | 误差 < 0.1% |
| 毛利率 | (营收 − 营业成本) / 营收 × 100% | 误差 < 0.1pct |
| 层级关系 | 毛利率 ≥ 净利率（正常情况） | 违反时必须解释原因（如巨额投资收益/营业外收支） |
| 报告期标注 | 每张财务表必须含"报告期"列 | 缺失即不合格 |
| 口径一致 | 年报/半年报/季报禁止直接横比 | 必须标注口径；跨期对比须说明换算 |
| 期数完整 | "最近5期"要求 5 期数据齐全 | 缺期标注"该期未披露/未获取" |
| 异常值 | 负 PE、超高毛利率（>90%）、ROE 骤变（±30pct） | 必须显式标注异常并说明，不得静默使用 |

## 四、估值与评级核验

| 核验项 | 公式/标准 | 容差 |
| --- | --- | --- |
| PE 逻辑 | PE(TTM) = 总市值 / 归母净利润(TTM) | 误差 < 5%（口径差异需说明） |
| 分位判断 | <30% 偏低、30-70% 合理、>70% 偏高 | 判断结论须与分位数值一致 |
| 目标价逻辑 | 最高价 ≥ 平均价 ≥ 中位数 ≥ 最低价 | 必须满足，违反即数据有误 |
| 上涨空间 | (平均目标价 − 现价) / 现价 × 100% | 误差 < 0.1% |
| 评级机构数 | 各评级档机构数之和 = 覆盖机构总数 | 必须相等 |

## 五、技术指标核验

| 核验项 | 标准 | 处理 |
| --- | --- | --- |
| 数据交易日 | 技术指标必须标注数据交易日 | 缺失即不合格 |
| 均线相对位置 | MA 数值与"现价在上方/下方"的表述必须一致 | 文字与数值矛盾时以数值为准改文字 |
| MACD 状态 | DIFF/DEA 大小关系与"金叉/死叉"表述一致 | 同上 |
| 超买超卖 | RSI>70 超买、<30 超卖；J>100 极端超买、<0 极端超卖 | 阈值判断须与 technical-analysis-rules.md 一致 |
| 支撑/压力 | 支撑位 < 现价 < 压力位（多数情况） | 违反时说明"现价已突破"而非照抄 |
| 派生指标 | IBS/乖离率/量能强度按 technical-analysis-rules.md 公式复算 | 抽查至少 1 项派生指标计算过程 |
| **成交量均线缺失** | 技术指标表**最新交易日**的 VMA5/10/20 常为空（收盘后未刷新时高发） | **优先自算**：用日行情序列算 `VMA_N = 近 N 日成交量均值`。实测自算与"用前一日 VMA 近似"可差 **17 个百分点**，前日值不可靠。仅当日行情序列也不可得时，才用最近可得 VMA 并注明"VMA 取 [日期] 值"。**禁止**直接写"量能数据缺失" |
| **区间涨跌幅期数** | "20 日/60 日涨跌幅"须有对应长度的行情序列 | 序列不足时标注"数据仅覆盖 N 个交易日"，**禁止**用不足期数冒充 |
| 复权口径 | 长周期涨跌幅与 K 线形态用同一复权方式 | 报告注明"前复权/不复权" |

## 六、资金流向核验

| 核验项 | 标准 | 处理 |
| --- | --- | --- |
| 正负号 | 净流入为正、净流出为负，与"流入/流出"表述一致 | 符号与文字矛盾必错 |
| 单位 | 资金表统一万元 | 万元/亿元换算标注 |
| 累计一致性 | 5日/10日累计净额与逐日明细加和方向一致 | 方向矛盾时以逐日明细重算 |
| 背离检查 | 资金流向与股价走势明显背离时必须点出 | 静默忽略视为核验不通过 |

## 七、新闻 / 公告 / 事件核验（六维硬性要求）

| 核验项 | 标准 | 处理 |
| --- | --- | --- |
| 维度齐全 | 新闻、公告、事件三类均已查询并有输出 | 缺任一类即不合格；数据不可得须写"未获取到数据（原因）"，禁止整节省略 |
| 失败类型判别 | 已区分 A 返回过大 / B 表在但为空 / C 全是噪声 / D 接口真失败 | A 类未拆窄重问就记为"缺失"→ 判定不合格，须重查 |
| 有效条目判定 | 剔除无关条目后统计有效条数 | 有效条数为 0 时，须写"已检索但未发现有效XX"，不得写"无新闻/无公告" |
| 标的相关性 | 每条新闻/公告确实涉及本标的 | 剔除仅关键词命中的行业新闻、同名公司、仅在名单/广告文中被提及的条目、含港股代码混淆的条目 |
| 缺失维度处理 | 缺失维度按 `scoring.md` §3 记 NA（不记 0 分、权重剔除，先完成拆窄重问），并在"未评分项"标注（`error-handling.md` 10.4） | 用估算值填充即不合格 |
| 时点标注 | 新闻标注发布时间，公告标注公告日期/编号 | 出现"近日""近期"等模糊时点即不合格 |
| 事实可追溯 | 事件量级（金额/股数/占比）来自公告或结构化数据 | 无出处的数字一律删除或改标"未经证实" |
| 传闻隔离 | 未经公告证实的内容单独分栏 | 与公告事实混写即不合格 |
| **表与新闻冲突** | 结构化事件表返回"暂无数据"（B 类），但新闻/公告侧命中了同类事件 | **两者并列呈现**：表记"未发现"，新闻/公告侧单列并注明来源与日期；**禁止**用其中一方覆盖另一方，也禁止只写"无此事件" |
| 公告优先 | 新闻与公告口径冲突时以公告为准 | 采用新闻口径须说明理由 |
| 去重合并 | 同一事件在新闻与公告中重复出现时合并为一条 | 重复计数会导致影响量级被高估 |
| 单位一致 | 事件金额统一万元、股数万股、比例 % | 混用未标注即不合格 |
| 定价判断 | 每条关键事件都给出"是否已被价格消化" | 缺失时不得用于支撑评级 |

## 八、逻辑一致性终检（发布前最后一道）

- [ ] 核心结论与各分项结论不互相矛盾（如基本面维度得分高但技术面维度得分低，须在正文中并列说明，不得互相覆盖）
- [ ] 综合评分 = 表中得分之和 / 已评分权重之和（`scoring.md` §3.2）。六项齐全时等于得分之和，并与上方综合评分一致
- [ ] 支撑位 < 现价 < 压力位 的相对位置与数值一致；违反必须解释
- [ ] 报告中所有数字在全文出现多次时保持一致（现价、市值等禁止前后不一）
- [ ] 数据基准日/交易日已标注，报告头部完整
- [ ] 覆盖范围合规：六维模式下六项齐全；专项模式未覆盖维度只在头部写"未查询（按您指定的范围）"，正文不单开章节；公告与事件已写入正文，报告中未出现「安全网」
- [ ] 第五章事件结论与综合评分的事件维度得分方向一致（重大利好而事件维度记 NA/低分必须解释）
- [ ] 报告未出现已废除的"风险特征结论"章节与"命中 N 项风险特征"措辞；安全网命中重大负面时「已披露重大事项提示」已输出并进风险提示第 4 条
- [ ] 事件三组 query（E1/E2/E3a/E3b）均已执行，11 类无整组遗漏

## 九、合规出口核验（★必过，判定标准见 `compliance-boundary.md`）

- [ ] 全文逐句过三问测试（时间指向 / 宾语指向 / 主体指向），无 L2 句残留
- [ ] 无 L2 特征词：推荐、建议、持有、建仓、减仓、加仓、止损位、目标位、值得、看好（引用他人观点时已标注来源）

- [ ] 多股对比的得分排序已附"非投资建议"标注
- [ ] 无"命中 N 项风险特征"等已废除措辞；无"不建议持有"式结论
- [ ] 免责声明已附，正文与 `compliance-boundary.md` §7 逐字一致（未缩写、未换标点），且为报告最后一节；未另附「建议继续提问」或「执行自检（内部记录）」

## 修正流程

1. 发现数据或逻辑问题 → 定位问题属于上述哪一节
2. 可通过重新查询修复的 → 重新调用 MCP 获取（换更窄的 query）
3. 属于计算/表述错误的 → 按公式复算修正
4. 无法修复的数据缺口 → 在报告中明确标注"数据待补/该期未披露"，**禁止编造**
5. 修正后重新过一遍对应核验项，直至通过
