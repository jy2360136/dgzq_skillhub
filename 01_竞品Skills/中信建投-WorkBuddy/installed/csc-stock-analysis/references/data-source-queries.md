# 当前数据源查询手册（翼答金融数据查询MCP）

> **本文件是数据源可插拔层的一部分**。当前默认数据源为**翼答金融数据查询MCP**（后端 `csc-ecomm-ra-llmtools-yida`）；换数据源时请**整体替换**本文件，并按 `references/data-source-config.md` 的"换数据源步骤"操作。本文件命名沿用"data-source-queries"，不强制带数据源名前缀；但本文件内容描述的是翼答的具体 query 句式与返回结构，换数据源时全部重写。

本文档汇总个股分析所需的翼答查询句式、返回结构（结构化 `result_page` vs 自由文本 `rich_text`）与实战口径，供快速查阅。

**调用方式**：通过 Bash 运行 `references/mcp_skillhub_call.py` 直连 SkillHub 端点（server/slug 见 `data-source-config.md`）；核心入参 `--question` 为自然语言提问（其余 7 个元数据 `session_id` / `add_info` / `source` / `user_name` / `version` / `user_id` / `logid` 由脚本按固定默认值注入，环境变量与缺省值见 `data-source-config.md`，**不要**在 Skill 内写死）。

**返回结构（翼答特有，务必先理解再写 query）**：

- **信封层有**两种**形态，解析必须同时兼容（2026-10-08 实测补充）**：
  - **形态 A（本会话实测）**：整段响应是**单个 JSON 对象** `{"events":[...]}`，没有 `data:` 前缀行；`events[].section` 承载内容。
  - **形态 B（早前会话实测）**：SSE 流，由多行 `data:{json}` 构成，需按行剥掉 `data:` 前缀后逐行 `json.loads`。
  - 解析器应先尝试"逐行剥 `data:` 前缀"，若一行都匹配不到，再退回"整体 `json.loads`"。只按形态 B 写解析器，遇到形态 A 会得到 0 表 0 文本，**极易误判为"接口无数据"**。
- **结构化数据的路径有两个，必须都遍历（2026-10-08 实测修正）**：
  - `result_page.components[].data.datas`（**形态 A 实测：数据直接在顶层 components**，此时 `answer_list` 为空数组）
  - `result_page.answer_list[].components[].data.datas`（形态 B 实测）
  - **两个路径都要取**。只遍历 `answer_list` 会漏掉形态 A 的全部数据；只遍历 `components` 会漏掉形态 B。以"`data.status_code==0` 且 `data.datas` 为非空列表"作为有效表的判据即可，不要试图先判断走哪条路。
  - 列定义取 **`data.columns[].key`**（中文列名，常带口径后缀，如 `收盘价:前复权`、`涨跌幅:前复权`），行数据键为列 `key`（同一行可能并存 `label`/`feKey` 等价键，**统一以 `key` 为准**）。
  - ⚠️ **不要用 `columns[].label` 取列名**：实测 `label` 可能被替换为无意义串（如两个列同时叫「风险等级B」），真实列名在 `key` / `index_name` / `feKey` 中。只按 `label` 过滤行会把有效表误判为"无结构化数据"。
  - ⚠️ `title_config.data.h1` 可作表标题，但**同名/相似标题会重复出现**，同一次响应内按 `(标题, 列名, 行数)` 去重，避免同一张表被重复计次。
- **自由文本答案** → `rich_text`：当 `section.show_type=="rich_text"` 时，`section.rich_text` 为纯文本片段（行业分类、新闻、公告、事件等维度常见）。需**按出现顺序拼接**后再从文本中**提取事实**，不能当作表格。
  - 同一 `id` 的 `rich_text` 是逐 token 分片推送的，单条只有 1~3 个字；必须全量拼接，只看最后一条会得到空串。
  - 返回体过大时工具会把全文落盘到临时 `.txt`，读该文件解析即可，**不等于数据缺失**。
- `section.text_answer` → 文本碎片，**不可**当结构化数据。
- ⚠️ **`datas` 里的数值字段可能是字符串，解析必须强制转 float**：实测同一张表的多数行是 `float`，但**最新一日**常以字符串返回（含科学计数法，如 `"-2.1792887609400005E9"`、`"2.233743505393E10"`）。若解析时用 `isinstance(v, (int, float))` 过滤，会**静默丢弃最新一行**——对"逐日序列取末值 + 5/10 日聚合"的字段（主力资金、成交额、融资余额、OHLC、估值）后果严重：2026-09-22 实测中该 bug 使 5 日主力净额由真实的 **-11,500 万元（净流出）** 变成 +144,663 万元（净流入），**方向完全反向**。统一做法：`v = float(str(v).replace(",", ""))`，转换失败才视为缺失。
- **关键差异（vs 聚源）**：翼答**没有** `api_name` 表名概念，也**不返回** markdown 表格；结构化统一在 `result_page`，非结构化统一在 `rich_text`。query 中**不要**按表名拼（如"查询XX表的XX字段"），直接用自然语言说"要什么指标"。

**通用调用纪律**：

- 一个 `question` 优先问**一组相关指标**：减少调用次数是提速主杠杆（见 SKILL.md「2.0 性能预算」）。行情不要打成十指标一句，日 K 线按 §1.3 的显式日期一次取开高低收和成交量。
- 若返回被截断/字段缺失 → **收窄**该问法（见 error-handling 10.x）；不要无脑重试同一长句。
- 长周期趋势与形态判断统一用**前复权**序列，报告中注明复权方式。
- 金额常见"万元/亿元"，出报告前统一换算为**万元**。
- **技术指标强烈建议本地算**：从日 K 线前复权收盘价序列本地计算 MA/MACD/KDJ/RSI/BOLL/VMA（见下文二）。翼答技术分析表字段名带口径后缀、稳定性差，不如本地算可控。

## 一、标的确认与行情

### 1.1 股票搜索（如需确认代码）

```
question: 搜索名称中包含"{公司名}"的A股股票，返回股票名称和代码
```

返回 `result_page` 组件，列含 `证券代码`、`证券简称`、`涨跌幅（%）`、`所属申万行业名称` 等。

> 一般用户已给"名称+6位代码"，可跳过搜索，直接用 `中际旭创300308` 这类写法。

### 1.2 实时行情快照（三句，禁止十指标一句）

价和量能一句，市值一句，估值一句：

```
① 查询{名称}{代码}最新收盘价、涨跌幅、成交额、换手率、量比
② 查询{名称}{代码}的总市值和流通市值
③ 查询{名称}{代码}的市盈率PE和市净率和股息率
```

> 2026-09-24 复测（三一重工600031）：十指标打成一句不再超时，但总市值、PE、PB、股息率两次返回的表形态不一致，且会落到年度序列或停在上一年末。**禁止**再把①②③合成一句。
> ① 返回约 30 行逐日表，列含 `收盘价:前复权`、`涨跌幅:前复权`、`成交额`、`换手率`、`量比`，末端应为 T 日。缺量比、换手率或成交额时只补缺的字段，不要改回十指标一句。
> ②③ 只采用最新交易日的值。返回年度序列、或日期停在上一年末时，重问该句；仍不是最新交易日则按缺失处理，禁止拿年度值当最新快照。
> ① 附带的约 30 行收盘价不够计算 MA60。长序列走 §1.3，不用这 30 行替代批4。
>
> **A+H 标的的市值口径（2026-09-30 实测 601066）**：`总市值` **≠** 总股本 × 收盘价。实测中信建投 2026-09-30 总市值 161,805,768,776.56 元（1618.06 亿元），而总股本 77.57 亿股 × 收盘价 23.03 元 = 1786 亿元；同期流通市值 149,595,304,000 元（1495.95 亿元）= 收盘价 × 流通 A 股 64.96 亿股（精确吻合），差额约 122 亿元对应 H 股按人民币折算。**纪律：A+H 标的不得用「总股本 × 收盘价」复算总市值**；报告中将总市值、流通市值与总股本三者并列，并注明总市值含 H 股折算口径。
> **市值/估值要逐日序列时改用显式日期问法**：问「查询{股}的总市值和流通市值」返回**年度序列**（末值停在上一年末，属 §1.2 的"重问"触发条件）；改问「查询{股}在{显式日期}的总市值和市盈率PE、市净率PB」可一次拿到约 31 行逐日序列、末端为 T 日，并顺带完成 PE/PB 的同日交叉校验（按 §1.2 规则重问对应那一句时优先用此句式）。
> **A+H 标的的总股本可能不随本句返回（2026-10-08 实测 宁德时代300750）**：本句只回总市值、流通市值两张序列，**不含总股本**。此时报告中省略"总股本"并列项并注明口径缺失，**不得**用 `总市值 ÷ 收盘价` 反推股本数量（A+H 标的下该商数无股本含义）。

### 1.3 日行情（K线，技术面本地算的原材料）

**首选（长序列，开高低收 + 成交量一次取齐）：**

```
question: 查询{名称}{代码}从{约一年前的 YYYY年M月D日}到{最新交易日的 YYYY年M月D日}的日K线数据，包含开盘价、最高价、最低价、收盘价、成交量（前复权）
```

> 2026-09-24 复测（三一重工600031，2025-09-24 至 2026-09-24）：一次返回 **243 行**，`开盘价:前复权`、`最高价:前复权`、`最低价:前复权`、`收盘价:前复权`、`成交量` 都在，末端为 T 日。问句可以写「日K线」。2026-09-22 的「含日K线的长窗口必 504」「开高低收加成交量打包必 504」是当时网关故障，不再作为现行限制。MA250 因序列不足 250 行，仍走批4b。
> **可把窗口放宽到 2 年以省掉批4b（2026-09-30 实测，新易盛300502）**：把日期区间写成 `2024-09-30 至 2026-09-30`（约两年）一次返回 **486 行**、五字段齐全、末端为 T 日，**MA5/10/20/60/120/250 全部可本地精算**，批4b 可整条省去、省一次调用。代价是返回体约 190KB（仍在小体积档）。默认仍写 1 年窗口；只要 MA250 必须出现在报告里（技术面表必填），就优先用 2 年窗口换掉批4b。
>
> ⚠️ **收盘价和日 K 线必须写显式日期区间，禁止写"最近一年"**：2026-09-22 实测「查询{股}最近一年的每日收盘价（前复权）」返回的是**上一个自然年 2025（20250102~20251231，243 行）**，而非截至 T 日的滚动一年。两者行数几乎相同，仅凭行数无法察觉，末值停在上年末会让 MA/MACD/RSI/BOLL 基于过期序列。该句 2026-09-24 未复测，禁令保留。**本禁令只约束收盘价和日 K 线序列。** 公告、事件问句里的「最近一年」照抄，不要改成显式日期。
> **强制自检（两道，缺一即判序列过期并重取）**：① 序列末值的 `时间区间` 是否等于 T 日；② 本地算出的 MA60/MA120 是否与批4b 的均线数值吻合。
> **区间一律以 `datas` 的 `时间区间` 为准**，不采信 `rich_text` 自述的覆盖区间。

**回退（短序列，约 30 行）：**

```
question: 查询{名称}{代码}最近30个交易日的日K线数据，包含开盘价、最高价、最低价、收盘价、成交量（前复权）
```

> 2026-09-24 复测「最近 60 个交易日」的同一句不再超时，但仍只回约 30 行，五个字段都在。相对窗口「最近 N 个交易日」的行数上限还在，加大 N 不会换来更长序列；长周期改回上面的显式日期问法。短序列不够算 MA60/MA120/MA250 时，长均线走批4b。
> 单独问「最近 30 个交易日的成交量」是否仍只回合计，2026-09-24 未复测。逐日成交量以本节能返回 `成交量` 列的序列为准；该列缺失时，量能强度改用成交额相对其 5 日均近似。

### 1.4 区间行情（振幅/回撤/涨跌天数）

```
question: 查询{名称}{代码}最近一年的区间涨跌幅、区间振幅、区间最大回撤、区间上涨天数与下跌天数
```

返回 `result_page` 组件。聚合类指标（振幅、回撤、涨跌天数）可直接用；精确 N 日涨跌幅仍走 1.3 序列自算。

## 二、技术指标（本地计算，推荐）

翼答不保证稳定返回完整技术指标表，且字段带口径后缀。**统一做法**：取 1.3 的前复权收盘价（+成交量）序列，在 Skill 内本地计算：

| 指标 | 计算 | 判断参考 |
| --- | --- | --- |
| MA5/10/20/60/120/250 | 收盘价简单移动平均 | 多头排列 MA5>MA10>MA20>MA60；空头反之 |
| VMA5/10/20/60 | 成交量简单移动平均 | 当日量 vs VMA_N 判断放缩量 |
| MACD | EMA12/EMA26 → DIF；DEA=EMA9(DIF)；MACD=2×(DIF−DEA) | DIF 上穿 DEA 金叉；柱体正负与扩张收缩 |
| KDJ | 取近 9 日最高/最低算 RSV→K/D→J=3K−2D | K 上穿 D 金叉；J>100 超买，J<0 超卖 |
| RSI(14) | 近 14 日涨跌幅均值比 | >70 超买，<30 超卖，50 分界 |
| BOLL(20,2) | 中轨=MA20；上/下轨=中轨±2×标准差 | 收盘价相对三轨位置；带宽收窄只记波动收窄，不判断方向 |
| 乖离率/量能强度 | (收盘−MA20)/MA20；量/VMA5 | 乖离>15 过热；量能强度>100% 放量 |

> 支撑位/压力位：用近 60 日高低点 + 近期密集成交区近似；主力持仓成本翼答不给稳定值，可标注"数据来源未提供，以 MA60 成本区近似"或跳过该字段。

## 三、基本面与财务

### 3.1 盈利能力与成长性（按组问，按报告期分行）

```
question: 查询{名称}{代码}最近5期的净资产收益率ROE
question: 查询{名称}{代码}最近5期的销售毛利率和销售净利率
question: 查询{名称}{代码}最近5期的营业总收入及同比
question: 查询{名称}{代码}最近5期的净利润及同比
question: 查询{名称}{代码}最近5期的每股经营现金流量净额
```

返回 `result_page` 组件，行按 `时间区间`（报告期，如 `2026-06-30`）排列，列含指标值。

> 关键列：`时间区间`（如 2026-06-30）、`报告期`（年报/半年报/一季报/三季报）、指标数额、`展示单位`。
> ⚠️ `报告期` 与 `核算方式=累计值` 必须同时标注。半年报是**上半年累计**，不可与一季报环比直接比规模。
> ⚠️ **ROE 不随批1a 返回（2026-09-30 实测，新易盛300502）**：批1a 问句里带了「净资产收益率ROE」，返回只有「营业总收入、营业总收入同比增长率」与「归母净利润及其同比」两张表，**ROE 列未随问返回**。每期分析须**单独补一条** `查询{名称}{代码}最近5期的净资产收益率ROE`（实测单问即返回「净资产收益率roe」列）；扣预算时把这条计入批1。

## 五、资金流向

### 5.1 个股主力资金（多日）

```
question: 查询{名称}{代码}最近30个交易日的主力资金流向，包含主力净流入额、大单净额、涨跌幅
```

返回 `result_page` 组件，行按交易日，列含 `主力净流入额`、`主力净流入占比`、`大单净额`、`涨跌幅(%)`、`最新收盘价(元)` 等。5日/10日累计净额、连续流入天数等聚合值从该序列本地算；返回过大时缩至 10 日。

> ⚠️ **实测只返回单列（2026-09-30，新易盛300502）**：本句返回的表只有一列 `主力资金流向`（金额，元），**未带回大单净额、资金比、超大单/中单/小单、涨跌幅**。报告「主力资金」表因此只能填「主力净额 + 方向 + 连续净流出天数 + 当日涨跌幅（涨跌幅取自批2①的序列）」，其余列写「未获取到数据」。**不要**为凑齐这几列再发一次同句。
> ⚠️ 同类日期列名是 `主力资金流向` 而非 `主力净流入额`，解析时按返回的 `columns[].key` 取，不要按手册里的字段名硬取。

## 七、研报、评级与舆情（新闻/公告/事件 → rich_text）

> ⚠️ 翼答的**新闻 / 公告 / 事件**三类，**普遍以 `rich_text` 自由文本返回**（本会话实测：结构化 `result_page` 多为空或无关）。处理方式 = 从 `rich_text` 文本中提取事实，**不**当表格。
> **公告 + 事件为安全网（任何模式必查）**；新闻仅在六维模式必查（专项模式记 `NOT_COVERED`，措辞"未查询（按用户指定范围）"）。覆盖范围内取不到必须显式降级（见 error-handling 10.x），**禁止整节省略**。

### 7.1 新闻舆情

```
question: 查询{名称}{代码}最近一周的新闻动态，只要5条的标题、发布时间和来源媒体
```

返回 `rich_text`。逐条核对标题/正文是否**确实涉及本标的**，剔除仅关键词命中的行业新闻。引用前清洗 HTML 标签。
>
> ⚠️ **本句有两种返回形态，都必须能处理（2026-10-08 两次实测同一标的 宁德时代300750，形态不同）**：
> - **形态 ①（逐条要点）**：返回**带条号、发布时间、来源媒体的逐条摘要**（本会话实测约 296KB，5 条，每条含"发布时间 + 核心内容 + 来源"）。此时按正常新闻表处理，日期列直接取返回的发布时间。
> - **形态 ②（聚合综述）**：返回体约 233KB，内容是**把新闻、公告、研报观点混写的综述段落**（带 `[^n]` 脚注），**不含逐条标题 / 发布时间 / 来源媒体**三列。
> - 形态 ② 的处理：① 从综述中抽出**可归属到本标的**的事实（含日期者优先），报告新闻表的"日期"列对无法确定的条目写 **"日期未返回"**，**禁止**编造或用"近期""近日"糊过去；② 综述中夹带的机构研报观点（目标价、评级）一律进报告"传闻与未经证实信息"栏并标注来源与"未经公告证实"，**不得**计入事件评分；③ 综述里与公告重叠的条目与 §7.2 公告结果**合并为一条**，报价以公告为准。

### 7.2 公司公告

```
question: 查询{名称}{代码}最近三个月的公司公告，只要标题和公告日期
```

返回 `rich_text`（公告正文片段序列）。从文本提取关键事实（日期、金额、股数、比例、方案条款），引用必须注明公告日期。

> ⚠️ query 中**不要**出现"定期报告""研报""点评"等词——会连带拉入研报库导致超限。
>
> **三个月窗口的覆盖自查（2026-09-30 实测 601066）**：问「最近三个月的公司公告…前15条」返回的条目**日期乱序、且实际只覆盖约 1 个月**（实测 2026-08-12 至 2026-09-09），**不等于三个月的完整列表**。取回后必须比较**最旧一条与最新一条的日期跨度**：跨度明显短于三个月时，用「查询{股}在{起}到{止}的公司公告，只返回公告日期和标题，最多15条」按显式日期区间补问（必要时拆两段，如 09-10 至 09-15、09-16 至 09-30）。否则会把"接口未返回"误写成"期间无公告"。
>
> **该句可能被接口误读（2026-10-08 实测 宁德时代300750）**：本句返回了"您的查询'三个月期'似乎不完整，我暂时无法针对此短语提供具体信息"式的**免责式回退**，只顺带给出 2 条动态。同一次分析改用**显式日期区间的补问句**后，返回了 2026-07 至 2026-10 的分红方案、分红实施、关联交易等带日期的条目。**判定：本句返回"查询似乎不完整 / 无法提供具体信息"时，视为未覆盖，立即改发显式日期区间补问句，不得据其回退式内容写"期间无公告"。**

> ⚠️ **同一金额可能在不同案由表述间重合，须并列标注（2026-09-30 实测 601066）**：实测同一标的的事件返回中同时出现「{历史案 A}专项基金（2023 年设立，近期无新增进展）」与「{新案 B}欺诈发行案（2026-09-10）」，且先行赔付基金金额在两处重合。富文本聚合可能把不同主体/案由的事项混写，报告须**并列呈现两种表述**并注明"以公司公告与监管机构文件为准"，禁止二选一当成确定事实，也不得只取金额较大的那一条。
>
> ⚠️ **E2 的结构化回购表不给"方案总额度与价格上限"（2026-10-08 实测 宁德时代300750）**：E2 返回的回购表列只有 `目的 / 进度 / 计划起始日 / 计划截止日 / 实施公告日 / 占总股本比例 / 支付金额 / 回购均价 / 最新回购日期`，**没有方案金额区间与价格上限**。这两个字段是事件量级（≥50 亿 / 10~50 亿 / <10 亿）的判定依据，缺了会让事件维度评分失据。补法：**在同属 E2 类目下单问一次**，如「查询{股}{回购方案时间}回购方案的金额上限和价格上限，以及{A 股第 N 期员工持股计划}的授予价格、覆盖人数与业绩考核目标」（实测一次返回方案额度、价格上限、用途、期限、进度，以及员工持股计划规模与受让价）。**注意**：补问返回的"累计回购金额/股数"与 E2 结构化表的 `支付金额` 可能不一致（实测同一标的出现 2.00 亿元与 33.03 亿元两种表述），须按"并列呈现 + 以公司公告为准"处理，禁止二选一。

## 八、查询组合建议

### 单股模式（默认执行计划：分批宽问；调用方式恒为串行单发，见 SKILL.md 2.0）

> **模式与批次对应**（覆盖范围判定见 SKILL.md Step 1；预算见 SKILL.md §2.0）：
> - **六维模式**：批1 ~ 批7 全跑（≈19 条 + Step 0 探测/核验）。
> - **专项模式**：只跑「覆盖集合内」的批次，**跳过**与主维度无关的批次；**批6 中的公告 + E1/E2/E3a/E3b 恒跑（安全网 5 条）**，新闻条按覆盖集合决定是否跑。
>   - **技术面专项**：批2（价量能可复用 Step 0.3/0.4，市值与估值另两句）+ 批4/4b/4c（K线/长均线/关键位）+ 批5 资金流 + 批7 行业与市场 + **安全网 5 条** ≈ 12-14 条（跳过批1/批3/批6新闻）
>   - **财报 / 价值面专项**：批1（1a+1b+1c）+ 批2 行情快照 + 批3 估值分位 + 批7 行业与市场 + **安全网 5 条** ≈ 10-12 条（跳过批4/批4b/批4c/批5/批6新闻）
>   - **消息面专项**：批6（新闻 + 公告 + E1/E2/E3a/E3b 全 6 条）+ 批2 行情快照（供事件与价量交叉验证）≈ 8 条

| 阶段 | 做法 | 目标 |
