# 个股综合分析

## 分析维度与覆盖范围规则

六个维度是**默认覆盖集合**——用户未指定维度时全部覆盖（六维模式）；用户显式指定维度时按指定范围专项执行（专项模式）。覆盖范围由 **Step 1 的显式词表**判定，判定结果与命中依据须记录。


| #   | 维度        | 回答的核心问题                  | 落地位置     |
| --- | --------- | ------------------------ | -------- |
| 1   | **基本面**   | 行业景气、公司业务与经营质量；估值分位写在此项下 | 报告第二章    |
| 2   | **财务**    | 盈利、成长、偿债、现金流             | 报告第二章财务表 |
| 3   | **技术面**   | 趋势、动量、关键位                | 报告第三章    |
| 4   | **资金**    | 主力净额等；做技术面时一并给出          | 报告第四章    |
| 5   | **新闻**    | 近期市场信息及其与公司的关联           | 报告第五章    |
| 6   | **公告与事件** | 公司披露与已发生事件；任何范围都固定核查     | 报告第五章    |


**纪律**：

1. **覆盖范围由 Step 1 显式词表判定**：命中即裁剪，未命中一律回落六维；锁定场景（ST/ST 标的、风险类提问）强制六维、忽略裁剪
2. **专项裁剪时，公告 + 事件作为安全网仍必查**（任何模式都不裁剪）；新闻仅在六维模式下必查
3. **未覆盖维度只在报告头部声明**为"未查询（按您指定的范围）"，正文不单开章节，不写"不构成任何判断"。**禁止**写成"无风险 / 无异常 / 正常"——未覆盖 ≠ 无风险。保留下来的章节从「一」连续编号
4. **数据缺失（NA）≠ 未覆盖（NOT_COVERED）**：取数失败记 `NA` 并按 `references/error-handling.md` 显式降级；按用户范围未查询记 `NOT_COVERED`。两种措辞在报告中**禁止合并成一句话**，否则用户分不清"没查"与"查不到"
5. 维度定义由本 Skill 规定；数据源如何提供（表名/接口/字段）属数据源适配层事务，见 `references/data-source-config.md`



## 功能概述

本skill围绕一个或多个明确A股标的，组织数据服务和研究方法，完成六类信息的综合分析：

1. 基本面：行业、竞争格局、公司业务和经营质量，估值分位写在此项下；
2. 财务：盈利、成长、偿债、运营和现金流；
3. 技术面：趋势、动量、位置、量价和关键位；
4. 资金：主力净额等，做技术面时一并给出；
5. 新闻：近期市场信息及其与公司的实质关联；
6. 公告与事件：公司正式披露，以及业绩、回购、增减持、重组、诉讼、监管等已发生事件。任何范围都固定核查。

本 Skill 只采用数据源原生指标与明确定义的派生计算，不引入任何数据源外的私有复合指标；所有结论都必须落到具体字段值上，取不到的数据显式标注降级，不靠推测填补。

数据源为可插拔架构，详见 `references/data-source-config.md`（当前默认：翼答金融数据查询MCP，工具底层名 `csc-ecomm-ra-llmtools-yida_tools_yida`）。换数据源时只改此文件 + `references/data-source-queries.md`，主框架零修改。

> ⚠️ **取数纪律（勿回退）**：本 Skill **不安装、不依赖任何 MCP 连接器**。所有取数统一通过 Bash 运行 `references/mcp_skillhub_call.py` 直连 SkillHub 端点完成，**禁止**调用 `mcp__`* 形式的连接器工具、禁止改用 web_search / 训练数据替代。端点 / server / slug 的唯一定义点在 `references/data-source-config.md`。

输出强调：事实先行、口径一致、数据可追溯、风险可落地。

**能力边界（速览）**

- **对象**：只分析明确的 A 股标的。未点名个股而问大盘、指数、行业比较、板块轮动或入场配置时，立即结束，禁止借用本技能的数据通道
- **支持**：单股综合分析、多股统一口径比较、技术 / 财务 / 事件专项分析
- **不输出**：收益预测、买卖与仓位指令、目标价、止损价、个性化持仓建议
- **关键位与评分**：仅作数据与规则结果展示
- **数据缺失**：记为「不可得 / 不可评分」；**未知不等于负面**

完整口径见「When to Use」与「When Not to Use」；约束落地见铁律 3、11、12。

## 核心铁律（每次执行必须遵守，不可绕过）

> **分组原则**：按**执行阶段**分四组，编号只表示**时序**；**优先级由组标题承载**，不以位置暗示优先级。



### ① 门控与前置（最高优先级，先于一切取数）

**对象门控（先于第 1 条 API Key，未通过则不查 Key、不取数）**：先判断问句属于哪一类。

- **问错对象**：用户未点名 A 股（无股票名称、无代码），且问题是大盘、指数、市场风格、行业比较、板块轮动、入场或资金配置。立即结束。不查 Key，不探测接口，不取数，不写解析脚本。原样返回下面两句，不得增删：

> 个股综合分析只核验已点名的 A 股。这次没有明确个股，本技能到此结束，不分析大盘，也不比较行业或入场方向。

禁止复用本技能的数据通道做大盘或行业事实核查，禁止先给客观行业强弱再把决策权留给用户，禁止改走其他技能继续回答。

- **名称没说清**：用户要分析个股，但名称或代码不足以确认。请用户补充名称或代码。补上之前不查指数、不查板块，也不套用上一类的结束话术。
- **已点名个股**：进入第 1 条及后续流程。只分析点名的个股。指数和所属行业只作这些个股的校准，不展开成大盘简报或行业排名。买卖、仓位、入场按铁律 11 处理。

1. **API Key 门控优先**：对象门控已通过后，任何取数前先检查环境变量 `CSC_SKILLHUB_API_KEY` 是否已配置；**未配置、Key 无效或额度耗尽，一律立即终止本次调用**，禁止任何降级或绕过，按「API Key 门控」章节原样返回引导提示。调用 MCP 接口服务时必须带 `X-API-Key`（取 `$CSC_SKILLHUB_API_KEY`，**禁止写死 Key**）与 `X-Calling-Skill-Id` 两个请求头
2. **数据源唯一**：所有取数只走 **SkillHub 直连端点**（详见 `references/data-source-config.md`），**禁止**用 web_search / 训练数据替代；接口不可用时按 `references/error-handling.md` 降级并明确告知用户



### ② 标的与范围

1. **标的范围与写法统一**：只分析**明确的 A 股标的**；写法一律"股票名称 + 6位代码"（如 `三一重工600031`），由数据源内部补全为标准代码；用户只给名称时必须先确认代码再继续。非 A 股标的（美股/港股/基金/期货/数字货币等）、或标的不明且无法确认时，按「When Not to Use」拒绝本次分析，**不得改走其他数据源、不得凭训练数据作答**。未点名个股而问大盘或行业入场的，走对象门控，不按「请用户补代码」处理。用户要分析个股但名称没说清时，才要求补充名称或代码
2. **覆盖范围显式化**：默认六维全覆盖；用户显式指定维度时按 Step 1 显式词表专项执行，其中**公告 + 事件仍必查**（内部称安全网，不写入报告）；未覆盖维度只在报告头部声明"未查询（按您指定的范围）"，正文不单开章节；覆盖范围内取不到的写"未获取到数据（原因）"并记 `NA`。**未覆盖（**`NOT_COVERED`**）与数据缺失（**`NA`**）禁止混写**，两者都禁止静默跳过



### ③ 数据质量与口径

1. **实时行情二次核验**：涉及"最新价/涨跌幅/成交量"的实时数据必须**两次查询比对一致**，不一致第三次取多数（详见 Step 0.4 与 `references/data-validation.md`）
2. **单位统一**：报告金额统一**万元**（超亿元可括注），股数**万股**，指标**%**；禁止万元/亿元混用不标注
3. **技术面只用当前数据源原生指标 + 允许的派生计算**：原生指标限 MA / MACD / KDJ / BOLL / RSI / 支撑压力位 / 主力持仓成本；派生计算限 `references/technical-analysis-rules.md` §一 明确的 **4 类**（日内收盘强度 IBS、MA 乖离率、N 日区间涨跌幅、量能强度）。**禁止引入数据源未提供的私有复合指标**；具体口径与旧字段处置见「指标口径说明」节（该节结论**随数据源变化即作废**，字段名不回写本条铁律）
4. **对比口径一致**：多股对比必须统一时间窗/报表期/复权方式/指标定义，禁止跨期横比



### ④ 输出与合规边界（合规检查为最高优先级，与 ① 组门控同级）

1. **禁止无依据结论**：所有判断必须引用具体字段值；数据缺失时明确降级，禁止脑补
2. **报告必含免责声明与数据基准日**：免责声明单独成节，正文原样照抄 `references/compliance-boundary.md` §7，不增删、不改写、不换标点、不缩写；报告到此结束（2026-09-24 起废除「建议继续提问」，亦不输出「执行自检（内部记录）」）；所有数据标注交易日期
3. **合规检查必过（最高优先级，与 API Key 门控同级）**：仅可基于客观数据选股，**不得出现建议、预测等涉及证券投资咨询牌照的业务内容**。所有最终呈现给用户的文本（含章节标题、表格判断列、结论句）逐句过三问测试，判定与改写对照见 `references/compliance-boundary.md`（**唯一定义点**）。三问：**时间指向**（说将来→预测）、**宾语指向**（宾语是用户行为→建议）、**主体指向**（需"我们怎么看"→主观），任一命中即禁出，改写为规则化描述或删除。**免责声明不能治愈违规内容**——免责是兜底提示，不是合规证明。**明确禁出的输出类型**（非穷举，判定一律以三问测试为准）：**收益或价格预测**（含"确定性"预测与概率/情景/区间式预测）、**买卖指令**、**仓位指令**、**目标价**、**止损价**、**个性化持仓建议**；支撑位/压力位/估值分位/状态评分**只能作为数据与规则结果展示**，不得包装成上述任一类。**条件性研究判断**（研究假设类表述）只能按 `references/compliance-boundary.md` §4A 的五条硬约束输出（≥2 条事实支撑、反证同句、标置信度、逐句过三问、每报告 ≤2 条），任一不满足即删除
4. **未知不等于负面**：数据缺失（`NA`）在报告里写"未获取到数据"，按范围未查询（`NOT_COVERED`）只在报告头部写"未查询（按您指定的范围）"。**禁止在文字结论中把缺失引申为负面**——如"因数据缺失，该股存在未披露风险""财务数据缺失，经营透明度存疑""不确定性较大"等一律禁出。缺失只影响本次分析的**覆盖度与陈述范围**，**不构成对标的的负面事实**；负面事实只能来自已披露的客观数据（公告、财务、事件）。本条是文字层禁令，分数层对应规则见 `references/scoring.md` §3（`NA` 不记 0 分、不从总分基数外重复扣减），**两层必须同步执行**；与铁律 4「未覆盖≠无风险」构成正反两个方向的对称约束



## API Key 门控（对象门控通过后、取数之前）

对象门控未通过时不进入本节。第三方平台 Skill 的登录认证**必须经过 SkillHub**。因此本 Skill 在**发起任何取数之前**必须先做一次 API Key 检查：

1. **唯一链路 = SkillHub**：本 Skill 取数**只走 SkillHub 链路**（用户各自申请 Key），不使用本地连接器或其他地址
2. **检查**：运行环境中是否已配置环境变量 `CSC_SKILLHUB_API_KEY`（用户各自在 SkillHub 申请，每人不同、各有额度，变量名定义见 `references/data-source-config.md`）
3. **未配置 → 立即终止本次调用**：
  - **不得**尝试任何降级方案（不得改用 web_search / HTTP 直连 / 训练数据 / 其他数据源）
  - **不得**绕过鉴权访问接口
  - **直接向用户原样返回**以下引导提示，本次调用就此结束：

> 您好,需要 API Key 才能使用本功能。请前往 [https://skillhub.csc108.com/finly/?channelCode=workbuddy](https://skillhub.csc108.com/finly/?channelCode=workbuddy) 申请并配置 API Key 后重试。

1. **Key 无效 / 额度耗尽 → 同样立即终止**：接口返回鉴权失败（401 / 403 / `MISSING_API_KEY` / `INVALID_API_KEY`）或配额类失败（429 / quota exceeded）时，**一律终止本次调用**——**不重试、不换问法、不降级**。原样返回上述引导提示，并补一句具体原因（Key 无效 → 请检查配置是否正确；额度耗尽 → 请更换 Key 或等待额度恢复后重试）。禁止把"缺 Key / 没额度"包装成"未获取到数据"。
2. **已配置且有效 → 正常执行**，调用 MCP 接口服务时必须带上鉴权请求头（见下节）



### 鉴权请求头（调用 MCP 接口服务时必带）

### 指标口径说明（当前数据源原生体系）

**原生指标**（技术面统一采用，全部取自当前数据源字段）：均线体系（MA5/10/20/30/60/120/250）、成交量均线（VMA5/10/20/30/60）、MACD（DIFF/DEA/柱）、KDJ（K/D/J）、布林带（MID/UPPER/LOWER）、RSI、支撑位/压力位、主力持仓成本、量比、换手率。

**允许的派生计算**（唯一 4 类，均由上述原生数据直接算出；公式与阈值见 `references/technical-analysis-rules.md` §一）：

- 日内收盘强度 `IBS =（收盘价 − 最低价）/（最高价 − 最低价）× 100`
- MA 乖离率 `=（收盘价 − MA_N）/ MA_N × 100`
- N 日区间涨跌幅 `=（最新收盘价 / N 个交易日前收盘价 − 1）× 100`（N 取自日行情序列）
- 量能强度 `=（当日成交量 − VMA_N）/ VMA_N × 100`

**禁止引入：数据源未提供的私有复合指标。** 若历史资料或用户问及数据源不提供的指标字段，统一说明"该字段非当前数据源原生指标，本 Skill 以 MA/MACD/KDJ/BOLL/RSI + 支撑压力位等原生指标等价判断"，**不得把该字段名写进报告结论**。

## Process（流程主体）



### Step 0: 前期准备（对象门控、数据源连通性与标的确认）

**触发条件**：首次调用、上一次调用返回错误、或标的尚未确认

**跳过条件**：本轮已成功取到该标的数据。对象门控判定为问错对象时，不适用本跳过条件

**完成标准**：能正常返回目标股票数据，分析对象明确（单股或多股列表）

**步骤 0.0：对象门控（先于 API Key 与探测）**

按铁律第 ① 组「对象门控」分类。问错对象时，原样返回该条固定两句，本次结束，不进入步骤 0.1，也不进入「API Key 门控」。名称没说清时，只请用户补充名称或代码。已点名个股后，才继续下面的步骤。

**步骤 0.1：探测数据源**

发出一条最轻量的查询，用于确认当前数据源 MCP 可用：

```
query: 查询三一重工600031最新收盘价和涨跌幅
```

> 具体查询语法依当前数据源而定，详见 `references/data-source-config.md` 与 `references/data-source-queries.md`。

预期返回含实时行情字段的表格。若返回错误，转 `references/error-handling.md`。

**步骤 0.2：确认标的代码**

```
query: 搜索名称中包含"{公司名}"的A股股票，返回股票名称和代码
```

- 单股模式：确认 1 个代码
- 对比模式：确认 2-8 个代码（建议不超过 8，避免信息过载）
- 用户只给了名称时，必须先确认代码再继续；代码有歧义时向用户复述确认

**步骤 0.3：验证数据可用性**

照抄 `references/data-source-queries.md` §八 批2，分三句，禁止合成十指标一句：

```
① 查询{名称}{代码}最新收盘价、涨跌幅、成交额、换手率、量比
② 查询{名称}{代码}的总市值和流通市值
③ 查询{名称}{代码}的市盈率PE和市净率和股息率
```

**步骤 0.4：实时行情二次核验（强制，不可跳过）**

对批2①再发一次，逐项比对两次返回。②③不默认再发；总市值用 `最新价×总股本` 复算，PE/PB 与③的最新交易日值核对，不一致再重问对应那一句：


| 核验项        | 一致性标准                         | 不一致时处理                        |
| ---------- | ----------------------------- | ----------------------------- |
| 最新收盘价      | ①的两次结果完全一致                    | 第三次查询①，取三次中多数一致的值             |
| 涨跌幅        | 误差 < 0.1%                     | 同上；并用公式 `(最新价−昨收)/昨收×100%` 复算 |
| 总市值        | 与 `最新价×总股本` 误差 < 1%，且日期为最新交易日 | 超出误差或不是最新交易日，再重问②             |
| PE(TTM)/PB | ③为最新交易日的值                     | 日期停在上一年末或与行情明显脱节时，再重问③        |


- **盘中数据**两次查询间价格自然跳动属正常，此时以**第二次（较新）**为准，并在报告"数据截止"中标注精确时间
- **盘中检测（必做，2026-10-08 因遗漏返工）**：核验结束后**先判断取数时点是否落在交易日盘中**（当日 K 线未走完，如 A 股 09:30至11:30、13:00至15:00 之间）。若是盘中，**后续所有技术指标（MA/MACD/KDJ/RSI/BOLL/区间涨跌幅/量能）及打分的输入序列一律截到"最近完整交易日"**，当日盘中价只写进报告头部的"数据截止"、不混入指标序列（口径见 `technical-analysis-rules.md` 开篇"盘中交易日口径"）。判定方法：看 1.3 取回的日 K 线末行 `时间区间` 是否等于当天且成交额明显低于前若干日（如约为前一日的 2/3），即视为盘中未走完。**这条在 Step 0.4 就要定下来**，等到 Step 3 才发现会连带返工全部指标与评分。
- 两次返回的表结构/字段明显异常（错行、空表、明显偏离的异常值）→ 转 `references/data-validation.md` 的修正流程
- 核验通过后，后续步骤可放心使用 0.3/0.4 确认过的行情快照，不必每次重复核验
- 完整核验规则（表格结构/财务公式/估值逻辑核验）见 `references/data-validation.md`

### Step 1: 覆盖范围判定（默认六维 vs 专项裁剪）

**目标**：先判断任务形态（单股核查 / 多股对比），再判定本次分析的**覆盖集合**。

> **覆盖集合 = 主维度 ∪ 配套数据 ∪ 安全网**。规则版本：2026-09-23。

**判断顺序（不可颠倒）**：

1. **任务形态**：单股核查（1 只）/ 多股对比（2 只及以上）
2. **锁定场景检查**（命中即**强制六维**，忽略后续裁剪）：

  | 锁定场景       | 判定依据                             | 处理                                              |
  | ---------- | -------------------------------- | ----------------------------------------------- |
  | ST / ST 标的 | 名称含 ST/ST，或用户提及退市/重整/摘帽          | **强制六维**（摘帽、重整、退市判断依赖公告与财务，只看技术面无意义）+ Step 4 增强 |
  | 风险类提问      | 问法含"有没有风险 / 会不会暴雷 / 能不能买 / 安不安全" | **强制六维**（风险判断天然需要财务 + 公告 + 事件）                  |

  > 多股对比与"首次分析某标的"**不锁定**：默认六维，但允许用户显式指定裁剪（"技术面对比"有真实使用场景）。
3. **显式词表匹配**（命中即裁剪；一张词表、可复现，不靠"猜意图"）：

  | 意图类别     | 显式关键词（出现任一即命中）                                           | 主维度          | 配套数据                                                                     |
  | -------- | -------------------------------------------------------- | ------------ | ------------------------------------------------------------------------ |
  | 技术面      | 技术面、技术、均线、MACD、KDJ、RSI、布林、BOLL、K线、形态、支撑位、压力位、量价、量能、走势    | 技术面          | 资金面（1-2 条）+ 行业与市场校准（1 条）。理由：只看图形不看资金是既有 Pitfalls 点名的坑；行业/市场校准用于"顺势/逆势"判断 |
  | 财报 / 价值面 | 财报、财务、ROE、毛利率、净利率、营收、净利、现金流、负债率、估值、PE、PB、分位、股息率、安全边际、护城河 | 基本面 + 财务面    | —                                                                        |
  | 消息面      | 公告、事件、新闻、舆情、消息、回购、减持、增持、解禁、质押、分红、重整、摘帽、诉讼、立案、问询          | 新闻 + 公告 + 事件 | —                                                                        |

  > **财报与价值面合并为同一覆盖集合** `{基本面 + 财务面}`：两者数据几乎重合，分开会让词表判定变含糊。
  > 多意图并存时取**并集**（如"技术面 + 消息面" → 技术面 + 资金面 + 新闻 + 公告 + 事件）。
4. **安全网（任何模式固定执行、不可裁剪）**：公告 1 条 + 事件四组（E1/E2/E3a/E3b）4 条 = **5 条查询**，详见 Step 2.8。
5. **未命中任一词表 → 回落六维全覆盖**（默认路径）。

**专项模式输出范围参考**（判定为专项裁剪后，报告包含哪些维度；未列入的维度**整节省略**，只在报告头部声明"未查询（按您指定的范围）"，正文不留空章，章节号顺延）：

- 技术面专项：技术面章节展开 + 资金面核心状态 + 行业/市场校准；基本面、财务面、新闻**未覆盖**
- 财报 / 价值面专项：基本面与财务表展开 + 估值分位；技术面、新闻**未覆盖**（资金面亦不取数）
- 消息面专项：新闻 + 公告 + 事件章节展开；基本面、技术面、财务面**未覆盖**
- 多股对比：默认六维等权对比；用户显式指定时按**同一覆盖集合**逐只对比（口径必须一致，见 Step 3.6）

> ⚠️ **未覆盖 ≠ 无风险**：未覆盖维度只在报告头部写"未查询（按您指定的范围）"，**禁止**写成"无风险 / 无异常 / 正常"，也禁止再开一节写"未查询。不构成任何判断"。
> ⚠️ **未覆盖（**`NOT_COVERED`**）≠ 数据缺失（**`NA`**）**：前者是"按用户指定范围没查"，后者是"查了没拿到"，两者措辞**禁止合并成一句话**。数据取不到时按 `references/error-handling.md` 显式降级，在对应章节写"未获取到数据（原因）"，**禁止静默跳过**。章节标题只写名称，不附加"安全网""已固定核查""无重大负面"等过程说明。
> ⚠️ **禁止由单维度数据外推其他维度结论**：技术面专项不得据此判断公司质地，财务专项不得据此判断价格位置。

**完成标准**：已明确任务形态、覆盖集合（主维度 + 配套数据 + 安全网）、判定依据（词表命中词 / 锁定场景 / 默认回落），并记录原因

#### 2.0 性能预算（硬性，取数前先读）

> **实测教训**：不控制取数量与问法宽度，单股六维分析会从数分钟膨胀到 20 分钟以上（快照见 `references/data-source-resilience.md`）。以下为硬约束。


| 项目           | 预算                                                                                                                                                        | 超标处理                             |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| MCP 取数次数（单股） | **六维模式**：≤ 22 次（含 0.1 探测与 0.4 二次核验），**默认走分批宽问计划 ≈19 条**（见 `references/data-source-queries.md` §八）；**专项模式**：≤ 16 次（默认 ≈12-14 = 主维度相关批 + 安全网 5 条）。不要退回逐指标窄问 | 超过先自查是否按 §八 合并问法执行；专项模式超出说明裁剪未生效 |
| 单次返回体        | 结构化 `result_page` ≤ 100KB 且无大段无关长文本；`rich_text` 靠条数限制词控量（如"只要8条标题"）                                                                                       | 超过即按该批「拆分回退」列拆窄（A类，至多2次）         |
| 报告对话正文       | ≤ 250 行                                                                                                                                                   | 正文只保留结论与模板要求的关键表。日K、逐日资金、公告原文用完即弃，禁止另写取数明细或数据附录 |


**取数方式（架构约束，与数据源无关）：按顺序逐条查询。** 过程说明写「按顺序查询」。Step 0 探测+核验通过后，按下方 A/B/C 清单**顺序逐条通过脚本取数**，每条拿到结果再发下一条；绝不在同一条消息里并列多条取数 Bash 调用。失败按「重试一次」处理，**仅命中限流才短退避**（具体秒数由环境层定）；串行本身已形成天然间隔，**不插入固定 sleep**。每次取数 = 一次 `python3 references/mcp_skillhub_call.py --server <server> --slug csc-stock-analysis --question "<问题>"`。

提速只有两个杠杆：**减少调用次数 + 提高单查询信息密度**。**并发不是杠杆**——能承受多大并发是数据源属性，声明在 `references/data-source-config.md`，本文件不写死任何并发数，也不因换源而改。

**批次即「分批宽问计划」**（句式照抄 `references/data-source-queries.md` §八，结构化区合并问、富文本区保持拆分）：

- **批次 A（技术/财务/估值）**：§八 批1 财务打包（1a+1b+1c）、批2 行情快照（Step 0.3 已取则复用，量能在①）、批3 估值分位、批4 K线（显式日期，开高低收+成交量，技术指标本地算）、批4b 长均线、批4c 关键位与成本
- **批次 B（资金/行业市场）**：§八 批5 资金流30日 + 融资余额（聚合值本地算）、批7 行业+市场（合并问）
- **批次 C（舆情与事件·保持拆分）**：§八 批6 共 6 条——新闻、公告、E1、E2、E3a、E3b（均照抄 2.8.x 窄 query；此区体积最大，**默认不合并**，超限按拆分回退缩窗）

> A/B/C 只是**查询清单的分组**，用于规划取数顺序与自查遗漏，**不是并发单位**——批与批之间、批内各条同样串行。若某条报「返回体过大」，其重试与相邻查询之间自然隔开即可。

> ⚠️ **动作自检**：如果你正打算把多条 query 并列写进同一条消息一起发出，立刻停手——那是并发调用。一次只发一条，拿到结果再发下一条。

**禁止的宽问法（会拉回几十倍无关内容）**：

- 「查询{股}最近一周的新闻动态」→ 必须补 `只要最近 8 条的标题、发布时间和来源媒体`
- 「查询{股}所属的行业板块、概念板块」→ 概念板块表含 30+ 条长描述，只为拿行业分类时改问 `所属申万行业分类`
- E1 业绩预告查询 → 措辞中**禁止**出现「定期报告」「研报」「点评」，否则连带拉入研报库
- E3 风险类 6 类合并问 → 超限率极高，已预拆为 E3a（质押/重组/诉讼监管）/ E3b（高管/停复牌/再融资/退市），**照抄 2.8.3 的 E3a/E3b 即可，禁止再合并回一句**
- 「前十大股东股权质押」全量问法 → 历史很长，改问 `最新股权质押比例` 或限定时间窗

**输出纪律**：用户只收到一份按报告模板写的文件。对话正文不超过 250 行，只保留结论与模板要求的关键表。日K、逐日资金、公告原文算完即弃，禁止另写「取数明细」或数据附录。一次性生成超长 markdown 是仅次于宽问法的耗时来源。

#### 2.2 K线与技术指标

句式照抄 `references/data-source-queries.md` §1.3 / §八 批4。首选是显式日期区间的日 K 线，一次包含开盘价、最高价、最低价、收盘价、成交量（前复权）。本步禁止写「最近一年」；公告和事件问句不适用这条禁令。「最近 N 个交易日」只作短序列回退，大约只有 30 行。

- **技术指标一律从该日 K 线序列本地算**（MA/MACD/KDJ/RSI/BOLL/量能，方法见 `references/data-source-queries.md` §二）。翼答技术指标表字段带口径后缀、稳定性差，下述 query **仅作本地计算不可用时的回退**，默认不发：
`查询{名称}{代码}最近20个交易日的技术指标，包括MA5、MA10、MA20、MA30、MA60、MA120、MA250、MACD、KDJ、RSI、布林带、支撑位、压力位、主力持仓成本`
- 日行情序列用于：计算 N 日区间涨跌幅、IBS、MA 乖离率、量能强度、识别经典形态（W底/M头/三角形/旗形）、确认支撑压力有效性；序列同时是 5日/10日资金净额等聚合值本地算的原料



#### 2.3 基本面与财务（价值分析/财报对比优先）

- 5日/10日累计净额、连续流入天数等聚合值**从 30 日序列本地算**，不单独发查询；窗口过大触发拆窄时缩至 10 日

#### 2.6 行业与市场环境（判断是否顺势）

句式照抄 `references/data-source-queries.md` §八 批7，一条问完。不要改问「行业板块、概念板块」。

- 用于识别行业景气、板块强弱、市场风险偏好

#### 2.8 新闻、公告与事件（六维模式必查；专项模式：公告 + 事件为安全网必查，新闻按覆盖集合）

**2.8.1 新闻（六维模式必查；专项模式按覆盖集合，默认不查）**

```
query: 查询{名称}{代码}最近一周的新闻，只返回新闻标题、发布时间、来源媒体，不要返回正文，最多8条
```

- 用途：识别市场关注点、突发消息、情绪拐点、媒体质疑
- 必须**逐条核对新闻是否确实涉及该标的**，剔除仅因关键词命中的行业新闻/同名公司新闻
- 引用须标注**发布时间**与**来源**；原文含 HTML 标签时先清洗

**2.8.2 公司公告（安全网，任何模式必查）**

```
query: 查询{名称}{代码}最近三个月的公司公告，只返回公告日期、标题、公告编号，前15条，不要正文
```

- 用途：核实公司官方口径——定期报告、回购、增减持、股权激励、分红、重组、担保、诉讼、质押、监管函件等
- 公告类返回常为**正文片段而非结构化表格**：须从中提取日期、金额、股数、比例、方案条款等事实
- 引用**必须注明公告日期/公告编号**；与新闻口径冲突时**以公告为准**

**2.8.3 公司事件（安全网，任何模式必查）**

> ⚠️ **不要把 11 类塞进一句 query**。实测证明：自由拼词极易漏类（漏"业绩预告/业绩快报"是高发错误），
> 且类别过多会触发返回超限。必须按下方 **E1 / E2 / E3a / E3b 四组分别提问**，逐组扫描。

```
E1 业绩类：查询{名称}{代码}最近一年发布过的业绩预告和业绩快报，包括预告类型、变动幅度与变动原因
E2 权益变动类：查询{名称}{代码}最近一年的重大事项，包括回购、增减持、股权激励、限售解禁、分红送配
E3a 风险类（质押/重组/诉讼监管）：查询{名称}{代码}最近一年的重大事项，包括股权质押、资产重组与对外投资、诉讼仲裁与监管问询
E3b 风险类（高管/停复牌/再融资/退市）：查询{名称}{代码}最近一年的重大事项，包括高管变动与停复牌、再融资、退市风险警示
```

**提问硬约束**：

- E1/E2/E3a/E3b 四条 query **照抄使用**（仅替换名称与代码），**禁止自行删减类别或改写措辞**；E3 已预先拆为 E3a/E3b 两类，不要再合并回一句
- 组内类别不得跨组混问；某组返回超限 → 按 `error-handling.md` 10.2 拆到单个类别再问
- E1 到 E3b 仍照抄「最近一年」，禁止因行情序列的「禁止最近一年」改写措辞。取回后看事件日期：某一组最新一条早于近 3 个月时，只按该组用显式日期或单类补问一次；四组都早于近 3 个月时，只补 E1。补问后仍无近 3 个月记录，才对该类写「未发现」。禁止把上一个自然年的结果直接滤成「未发现」
- E1/E2/E3a/E3b 四条全部跑完才允许进入 Step 3，**禁止只跑其中部分就下结论**

按以下清单逐类扫描，**命中即记录，未命中写"未发现"**：

| ------------------ | --- | ------------------------------ |
| 业绩预告 / 业绩快报        | E1  | 预告类型（预增/预减/扭亏/首亏）、变动幅度、变动原因    |

**调用纪律**：

- E1/E2/E3a/E3b **分开提问**，避免返回体过大被截断；一次只查一只股票
- 时间窗默认「新闻 1 周 / 公告 3 个月」。事件问句照抄「最近一年」，报告摘取近 3 个月；日期落在上一个自然年时按上面的补问规则处理，不要直接滤掉。用户指定时间窗时以用户为准
- **返回体过大被拒 ≠ 数据缺失**：工具报 `exceeds maximum allowed tokens` 时**必须拆窄重问**（限定条数 → 缩短时间窗 → 拆单类），重问成功即视为已覆盖，详见 `references/error-handling.md` 10.2
- **提问避坑**：事件/公告查询中**不要写"定期报告""研报""点评"**，会连带拉入研报库导致超限
- **有效条目判定**：新闻须逐条核对与本标的的实质关联；仅在名单/广告文中被提一句的条目应剔除。**剔除后剩余 0 条**时，写"已检索但未发现涉及本标的的有效新闻"，按降级处理（不得写成"无新闻"）
- 「查询成功但表内值为暂无数据」属**有效结论**（记录为"未发现"），不是数据缺口
- **表与新闻冲突时并列呈现，不得互相覆盖**：结构化事件表返回"暂无数据"，但新闻/公告侧命中了同类事件（如实测中诉讼仲裁表为空、新闻却有开庭公告）→ 表中记"未发现"，新闻/公告侧单列并注明来源与日期，**禁止**只写"无此事件"
- 同一事件在新闻与公告中重复出现时**合并为一条**，注明来源与日期
- 事件判断须区分「**已发生且已披露**」与「**仅有传闻/预期**」，后者不得写成既成事实

**完成标准**：**公告、事件两类均已查询**（安全网，任何模式不可省）；新闻在**六维模式**下已查询、**专项模式**下记 `NOT_COVERED`（措辞"未查询（按用户指定范围）"，**不得记** `NA`、不得写"无新闻"）。命中项已记录（类别 + 日期 + 事实 + 性质判断），未命中项已写"未发现"；真缺失项已按 `error-handling.md` 10.4 判定（拆窄重问 → 仍失败才记缺失），在综合评分中按 `references/scoring.md` §3 记 **NA**（不记 0 分、该维度权重从总分基数剔除），并在"未评分项"中标注原因；**跳过重试直接标 NA 的按执行不合格处理**（scoring.md §3.1 防偷懒纪律）

### Step 2.5: 门控短路（取数完成后、深度分析前，条件触发）

**目标**：对明显无需走全流程的标的，用轻量轨道节省分析成本，避免"为了完整而完整"。**单股模式触发，多股对比不触发**（对比本身就要全量数据）。

**短路判定（按序检查，命中即走对应轨道）**：


| 门控            | 触发条件（须同时满足）                                                        | 输出轨道                                                                                                    |
| ------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------- |
| **G1 轻量否决简报** | ① 最近 3 期连续净利润为负 **且** ② PE(TTM) 为负或缺失 **且** ③ 非ST股（ST 走 Step 4 专轨） | 只出简报：核心数据表 + 3 条关键数据证据。报告写「本报告为连续亏损简报。最近 3 期净利润为负，市盈率（TTM）为负，明细见下表。」不写 G1。跳过 Step 3/4，简报尾部注明「如需完整分析请说明」 |
| **G2 小盘微利简版** | ① 流通市值 < 50亿 **且** ② 最近一期营收 < 5亿 **且** ③ 用户未明确要求深度报告               | 简版报告：行情 + 核心财务 + 估值分位 + 一段式结论；技术面与资金面只给关键位，不做全指标展开                                                      |
| **G0 全流程**    | 以上均未命中                                                             | 走 Step 3 完整分析（默认）                                                                                       |


**短路纪律**：

- 短路**只省输出篇幅，不省核验**——G1/G2 轨道同样必须执行二次核验与数据核验
- 短路**不省安全网**（公告 + 事件）——重大负面事件是否决简报的核心证据，必须扫描后在简报中列出；六维模式下新闻同样不可省，仅技术面与资金面可压缩
- **专项模式不执行 G1/G2 门控**：门控只服务六维模式。G1 判定条件是"连续 3 期净利为负"，需要财务数据；而技术面专项恰恰不查财务——保留门控会出现"为了判断要不要省成本、先去取被裁掉的数据"的悖论。专项模式本身已省成本，无需再短路
- 用户明确说"完整报告/深度分析/全维度"→ **旁路 G2**，强制全流程
- 短路触发时必须在报告头部注明类型，不装作全流程产物。连续亏损写「本报告为连续亏损简报。最近 3 期净利润为负，市盈率（TTM）为负，明细见下表。」小市值写「本报告为简版。流通市值低于 50 亿元，且最近一期营业收入低于 5 亿元。」不写 G1、G2 或「轨道」
- 拿不准是否触发（数据缺失导致无法判定）→ 按全流程走，并在风险提示中注明数据缺口

### Step 3: 执行分析与多股对比

**目标**：形成"六维数据画像 + 规则化评分"，并在多股模式下给出统一口径下的可解释对比结论

> **信号判断规则与阈值**：[技术分析通用规则](references/technical-analysis-rules.md)



#### 3.1 第一步：基本面与财务事实梳理

1. 宏观与行业景气度
  - 宏观周期对行业影响（复苏/过热/滞胀/衰退）
  - 政策导向（扶持/监管/中性）
  - 行业生命周期与竞争格局（用行业指数涨跌幅 + 研报结论佐证）
2. 公司财务健康度
  - 盈利能力：ROE（摊薄）、销售毛利率、销售净利率及其趋势
  - 成长能力：营业总收入同比、净利润同比
  - 偿债能力：资产负债率、流动/速动比率
  - 运营能力：存货周转率、应收账款周转天数
  - 现金流：每股经营活动现金流量净额
3. 护城河与治理
  - 品牌、技术、规模、网络效应、特许经营能力（结合所属概念板块中的行业地位描述）
  - 股东结构稳定性（十大流通股东持股比例及变动）
  - 管理层执行力与治理稳定性
4. 估值水平
  - 相对估值：PE(TTM)/PB 及其**近三年历史分位**（当前数据源原生分位接口）
  - 绝对估值：仅在参数充分时给 DCF 方向性判断



#### 3.2 第二步：技术面状态核对（当前数据源原生指标）

1. 均线体系（趋势方向）
  - 短中期：MA5 / MA10 / MA20 的相对位置，判断短线节奏与多头/空头排列
  - 中长期：MA60 / MA120 / MA250，确认大级别方向
  - MA 乖离率：`（收盘价 − MA_N）/ MA_N × 100`，判断是否偏离过大
2. 动量指标
  - MACD：DIFF 与 DEA 的金叉/死叉、柱体正负与扩张收缩
  - RSI：>70 超买、<30 超卖、50 为多空分界
  - KDJ：K/D/J 的金叉死叉与超买超卖（J 值 >100 极端超买，<0 极端超卖）
3. 布林带位置
  - 收盘价位于 UPPER 之上：强势但需防回抽
  - 位于 MID 之上：多头占优
  - 位于 LOWER 附近：弱势或超跌
  - 带宽收缩（UPPER−LOWER 收窄）：带宽处于低位，只记录收窄，不判断方向
4. 关键位与成本
  - 直接读取 `支撑位` / `压力位`
  - 对比现价与 `主力持仓成本`：现价高于成本→主力浮盈，低于成本→浮亏承压
5. K线质量与形态
  - 日内收盘强度 `IBS =（收盘 − 最低）/（最高 − 最低）× 100`，越接近 100 收盘越强
  - 基于日K线识别经典形态（W底、M头、三角形、旗形）与突破有效性
6. 量价关系
  - 量比、换手率、`（当日成交量 − VMA_N）/ VMA_N` 量能强度
  - 放量突破（量能强度 > 0 且价格创区间新高）：信号可靠性高
  - 缩量回踩（量能强度 < 0 且价格回调）：只记录量能方向与价格方向
  - 量价背离（放量下跌或缩量上涨）：需警惕



#### 3.3 第三步：资金流向分析

1. 个股主力资金
  - `主力净额` / `超大单净额` / `大单净额`：看当日与近期净额正负
  - `5日主力资金净额` / `10日主力资金净额`：判断资金持续性
  - `主力资金连续流入天数`：连续为正代表资金持续性较好
2. 杠杆与外资
  - 融资余额与融资净买入额：杠杆资金方向（净买入为正 / 净卖出为负）
  - 陆股通持股比例变化：持股占流通股本比例升降
3. 筹码结构（若数据可得）
  - 股东户数变化与户均持股变化
  - 十大流通股东持股集中度变化



#### 3.4 第四步：事件驱动分析（事件与消息面维度的分析落点）

对 Step 2.8 收集到的每条新闻/公告/事件，按三步判断，输出"事件 → 传导 → 影响"：

1. **定性**：利好 / 利空 / 中性存疑
  - 利好示例：回购实施中且已回购比例高、控股股东或董监高增持、业绩预告预增、重大合同中标、股权激励设定高考核目标
  - 利空示例：减持计划实施中、业绩预告预减或首亏、立案调查/监管问询、大额诉讼为被告、控股股东高比例质押、限售解禁临近
  - 中性存疑：仅有传闻或研报预期、无公告佐证 → 必须标注"未经公告证实"
2. **定量与时效**
  - 规模：金额/股数/占股本或市值比例，判断影响量级（是否触及"重大"）
  - 时点：已发生 / 进行中 / 仅有预案；距今天数决定是否已被价格消化
  - 持续性：一次性损益（如资产处置）不改写长期逻辑，需显式说明
3. **与价量交叉验证**
  - 利好但股价不涨、资金流出 → 说明已预期兑现或市场不认可，须点出背离
  - 利空但股价抗跌 → 说明可能已充分定价，不得机械看空
  - 重大事件日前后出现异常放量/缺口时，用 Step 2.2 的 K 线序列定位对应交易日

**输出要求**：

- 至少给出 **1 条最关键事件**的完整判断（事件 + 日期 + 量级 + 方向 + 是否已被定价）
- **六维模式**：标题为「新闻、公告与事件」。若三类均未命中，写"近期无重大新闻/公告/事件"，**不得留空或省略该节**
- **专项模式**：用户未指定新闻时，本章标题为「公告与事件」，不写新闻小节。有事实写事实；没有应关注事项写「未发现」；接口没返回写「未获取到数据（原因）」。命中重大负面清单时，在该章写出「已披露重大事项提示」（公告日期 + 事实 + 数值），并进风险提示第 4 条。标题和报告头部都不写「安全网」「已固定核查」「无重大负面」「未能核查」
- 存在"仅有传闻、未经公告证实"的内容时，必须与公告事实**分栏表述**，禁止混写

**异动归因分支（条件触发，2026-09-23 新增）**：用户明确问"为什么涨/跌"，或当日/近期出现显著异动时，按 `references/event-analysis-rules.md` §5 执行——① 异常确认（对比自身历史/行业/指数，不显著则写"未见显著异动"）→ ② 四层候选解释（市场层/行业风格层/公司层/交易结构层）→ ③ 因果验证五问（时间先后、信息增量、传导机制、横截面佐证、替代解释）。**证据不足时必须输出"存在多个候选原因，当前无法确认单一主因"并列出候选与证据强度，禁止强行指定主因**；禁止仅凭资金流入、主题标签或单条新闻定因果。候选解释需写出传导路径时，按 `compliance-boundary.md` §4A 条件性研究判断输出（≤2 条、带反证、标置信度）。

#### 3.5 第五步：综合评分与状态结论（合规检查必过）

1. **综合评分：按** `references/scoring.md`**（评分口径唯一定义点）的**固定权重口径**计算六维得分（分项阈值见 `technical-analysis-rules.md` §8），输出 `综合 XX/100` + 逐维得分 + **有效数据覆盖率** + **未评分项**（NA/NOT_APPLICABLE 处理见 scoring.md §3；覆盖率 <80% 只出分维状态与缺口，不出总分）。**不得**输出"强烈推荐/谨慎推荐/中性/观望/回避"等评级词
  - **用户只指定部分维度（不出总分）**：写「本次只评 [维度]：[得分] / [该维度满分]。覆盖率 [值]%，不足 80%，不出综合评分。」未查询和未获取到数据分两处写，措辞分别为「未查询（按您指定的范围）」与「未获取到数据」。不写英文状态码，不写仓库路径。
2. **技术面状态结论：只描述客观状态——均线排列状态、动量指标状态、价格相对关键位的位置（现价 vs 支撑位/压力位/主力持仓成本/MA20）。**不得**输出"建仓期/持股期/减仓期/观望期"、"入场条件"、"止损位"、"目标位"
3. **风险提示（必填）**：单独成节，写 3 条（行业/政策、业绩/估值、技术/市场；重大未决事件可第 4 条单列）。本节不放免责声明。
4. **免责声明（必填，报告最后一节）**：正文原样照抄 `compliance-boundary.md` §7 全文。



#### 3.6 多股对比矩阵（2只及以上触发）

**目标**：把多只股票放到统一框架中横向比较，输出统一口径下的数据差异与得分排序。

1. 对比维度（随意图切换）：
  - 综合对比：基本面、技术面、财报质量、资金情绪、**事件与消息面**（六维模式）
  - 技术面对比：均线排列、MACD/KDJ/RSI 状态、支撑压力位结构、量能
  - 财报对比：盈利质量、成长质量、偿债与现金流安全性
  - 价值面对比：PE/PB 历史分位、护城河稳定性
2. 输出方式：
  - 给出对比表（每只股票一行），维度列填**客观数据或规则化状态标签**，末列为综合评分
  - 给出各维度**数据极值标的**（如"ROE 最高：A（X%）"、"5 日主力净额唯一为正：B（+X 万元）"）与**固定口径得分排序**
  - 解释得分差异来源（至少 1 条，须引用具体数值）
3. **得分排序的合规边界**（铁律 11）：
  - 允许输出排序，因为口径固定、可复现（属 L1）
  - 排序必须标注 **"按固定口径评分排序（口径：六维 / 专项 XX 维度），非投资建议"**
  - **禁止跨口径排序**：专项得分**不得**与六维总分放进同一张表排序；专项模式下排序只能在**同一覆盖集合**内进行（逐只口径一致），并注明"专项口径与六维总分不可比"
  - **禁止**用"优先/首选/更值得/应优先关注"等措辞替代排序说明
  - 禁止给出"买 A 不买 B"式的二选一结论
4. 并列处理：
  - 若评分接近（分差 ≤ 3 分），不强行分胜负，输出"同级（分差 X 分）"
  - 明确区分两者所需补充的数据项

> **覆盖范围规则（替代原"六维硬性要求"）**：默认六维全覆盖；专项模式按 Step 1 覆盖集合执行，**未覆盖维度只在报告头部声明**。覆盖范围内取不到的，在该章写"未获取到数据（原因）"（记 `NA`）；按用户范围未查询的，只在头部写"未查询（按您指定的范围）"（记 `NOT_COVERED`），正文不单开章节。**两者都禁止静默，措辞禁止混用**；覆盖范围内维度禁止整节省略。章节标题只写名称。



## Report Template（报告模板）

过程说明和报告只用本节和 `templates/report-template.md` 里的中文，不写内部代号，不写仓库路径。

> **严格按照以下模板格式输出，不得随意增删章节、改变顺序或改变表格结构。**
> **例外（专项模式）**：按 Step 1 覆盖集合，**未覆盖维度整节省略**（不留空章节、不写"不构成任何判断"），只在报告头部声明"未查询（按您指定的范围）"。保留章节按原顺序从「一」连续编号。覆盖范围内的章节一律不得省略。呈现给用户的标题不加括号说明。
> 完整模板详见 [templates/report-template.md](templates/report-template.md)，以下为必须遵守的核心格式规范。



### 格式规则

- 金额统一换算为**万元**，保留整数（如 85269700 元 → 8527万元）
- 财务表格必须标注**报告期**（如"2026半年报"、"2026一季报"）
- 技术指标必须标注**数据交易日**
- 多股对比必须统一口径（时间窗/报表期/指标定义）
- 所有判断必须引用具体字段值，禁止无依据结论
- **报告正文禁止用半角** `~` **连接区间**（日期、价格、估值、阈值、业绩预告的金额与同比幅度都一样）。写「至」，例如 `2023-09-24至2026-09-24`、`5.43至11.22`、`30%至70%`、`72.14至81.16亿元`、`同比+60%至+80%`。数据源原文里的 `~`、`～` 不得照抄。同一段里成对的 `~` 会被 Markdown 当成删除线：`72.14~81.16亿元、同比+60%~+80%` 会在两个波浪号之间划出一条中线；复制后波浪号消失，粘成 `72.1481.16`、`+60%+80%`。本条只约束呈现给用户的报告；技能内部文档与取数问句不受此限。



### 输出章节（严格按此顺序）

**报告头部（必填）**：分析对象、分析日期、数据截止交易日、数据来源（当前金融数据源，默认翼答金融数据查询MCP；具体见 `references/data-source-config.md`）、分析意图、**本次覆盖范围**（格式见下）、数据覆盖率（评分口径，见 `references/scoring.md`）

> **「本次覆盖范围」字段（必填，措辞强制统一）**：
> `本次查询：基本面、财务。`
> `未查询（按您指定的范围）：技术面、资金、新闻。`
> `数据覆盖率：72%。未计入评分：新闻（未查询）、陆股通持股比例（未获取到数据）。`
> 未查询只写在头部，不为该维度单开章节。未获取到数据写在对应章节并带原因，两处措辞禁止合并，禁止把未查询写成「无风险」。全覆盖时不写「未查询」行。不写「已固定核查」「无重大负面」「未能核查」。不写英文状态码，不写仓库路径，不写「安全网」。

**一、核心结论（必填）**：一句话数据概览 + 综合评分 `XX/100` + 数据覆盖率 + 当前技术面状态（均线排列 + 动量 + 现价相对关键位位置）。不写仓库路径。

> 用户只指定部分维度时不出总分，写「本次只评 [维度]：[得分] / [该维度满分]。覆盖率 [值]%，不足 80%，不出综合评分。未查询（按您指定的范围）：[维度]。」

**二、基本面与财务（必填）**：

- 行业景气与政策（一句话结论 + 依据）
- 财务健康度表格（含报告期列）：ROE(摊薄)、销售毛利率、销售净利率、营业总收入同比、净利润同比、资产负债率、每股经营现金流
- 护城河与治理（1-2句）
- 估值判断：低估/合理/高估（PE(TTM)=[值]、PE近三年分位=[值]%、PB(LF)=[值]、PB近三年分位=[值]%、股息率=[值]%）

**三、技术面（必填）**：

- 趋势结构表：MA5/MA10/MA20/MA60/MA120/MA250 及排列状态、MA20乖离率、MACD(DIFF/DEA/柱)、KDJ(K/D/J)、RSI、布林带(MID/UPPER/LOWER)
- 动量与K线质量表：1日/5日/20日/60日区间涨跌幅 + 日内收盘强度 + 收盘价 + 距区间高低点位置
- 关键位：支撑位、压力位、主力持仓成本（现价与成本对比）
- 量能：量比、换手率、相对 5 日均量、5 日均量 / 20 日均量

**四、资金（必填）**：

- 主力资金表格（个股资金流向，金额单位万元）：日期、大单净额、资金比、连续流入天数
- 五日/十日主力净额、超大单/大单净额
- 融资余额与融资净买入额（若可得）、陆股通持股比例变化（若可得）
- 资金结论（一句话）

**新闻、公告与事件**（六维模式标题；专项模式未查新闻时标题为「公告与事件」。模板中的章号是全覆盖顺序，输出时按实际保留章节连续编号。标题不加括号）：

- 近期新闻要点（来源 + 发布时间，剔除无关条目；未查新闻时不写本块）
- 公司公告要点（公告日期/编号 + 关键事实；与新闻冲突时以公告为准）
- 事件表：事件类别 / 日期 / 关键事实（金额·股数·比例）/ 性质（利好·利空·中性）/ 是否已被价格消化
- 事件结论（一句话：最关键事件是什么、方向、量级、是否已被定价）
- **异动归因（条件块：用户问涨跌原因或出现显著异动时必出）**：异常确认 → 四层候选解释 → 因果验证；证据不足写"存在多个候选原因，当前无法确认单一主因"；候选解释按 §4A 输出（≤2 条、带反证、标置信度、与事实分栏）
- 有事实写事实；没有应关注事项写「未发现」；接口没返回写「未获取到数据（原因）」，**禁止整节省略**。传闻类须与公告事实分栏，标注"未经公告证实"

**六、综合评分与状态（必填）**：

- 综合评分：`XX/100` + 逐项得分 + 数据覆盖率 + 未计入评分的项目。不写仓库路径。
- 技术面状态：均线排列 / 动量指标 / 现价与支撑位·压力位·主力持仓成本·MA20 的相对位置（均为客观数据）
- 事件状态呼应：第五章关键事件的事实要点（公告日期 + 数值 + 当日价量表现）

> ⚠️ **禁止出现**：入场条件、止损位、目标位、执行建议、持有/建仓/减仓/加仓类措辞。支撑位/压力位只能作为数据源原生字段呈现，不得包装为操作指令。

**七、多股对比结论（条件必填：2只及以上）**：对比表（基本面/技术面/财报质量/资金流向/事件消息面/综合评分）+ **固定口径得分排序（须标"非投资建议"）** + 得分差异来源说明

**八、ST 增强分析（条件必填：ST/ST 股票）**：ST原因、重整进度、**摘帽条件清单（条件/是否满足/依据）**、控制权与重组的已披露事实

**九、风险提示（必填）**：3条，分别覆盖行业/政策、业绩/估值、技术/市场层面；若存在重大未决事件（诉讼/问询/解禁/减持），须在第4条单列

**十、免责声明（必填，报告到此结束）**：单独成节。正文原样照抄 `references/compliance-boundary.md` §7，不增删、不改写、不换标点、不拆句、不缩写，不并入风险提示，其后不另起章节。定稿全文如下：

> 本技能分析数据经第三方信息源采集加工，仅供参考；本技能仅开展个股公开信息核验与指标展示，不构成任何投资建议及操作指导，不对标的价格与收益做预判，输出的综合评分及相关内容不得直接作为交易决策依据；本技能采用固定权重评分体系运算，受模型逻辑、数据覆盖范围制约，分析结果存在局限性，无法穷尽全部市场影响因素，投资者需独立做出投资判断，自行承担全部投资风险，投资有风险，入市需谨慎。

## Common Pitfalls（常见陷阱）

- 用户只要技术面时，报告未声明未覆盖维度，使读者误以为其他维度无异常（**未覆盖 ≠ 无风险**）
- 专项模式下把"未查询（`NOT_COVERED`）"与"未获取到数据（`NA`）"混成一句话，用户分不清"没查"与"查不到"
- 把"未获取到数据（`NA`）"当成负面信号，在结论里引申出风险判断（**未知既不是正面也不是负面，只说明这次没拿到数据**；负面必须有已披露客观数据支撑）
- 为未查询的维度单开章节，或在标题上写「安全网」「已固定核查」
- 只看 K 线与财报，不查公告与事件，漏掉减持计划、业绩预告、立案问询等**已披露**的重大风险
- 把新闻热度当成事件影响，未区分"已公告事实"与"市场传闻"
- 多股对比时混用不同报告期口径，导致结论失真
- 只看财务指标，不看行业景气与政策方向
- 混淆"不复权/前复权"的行情数据，导致长周期涨幅计算失真（务必固定复权方式）
- 用单日波动解释长期价值
- 在数据不全时给出过度确定的结论
- 把 ST 博弈当作普通成长股逻辑分析
- 单次查询塞入太多维度，导致返回体超限被截断



## Gotchas（闭坑指南）

> **详细错误处理**：[错误处理指南](references/error-handling.md)



### 问错对象

- 用户未点名个股，问大盘、指数、行业比较、板块轮动或入场配置（如「分析当前大盘，入场哪个行业比较好」）
- 原样返回对象门控的固定两句，停止
- 不复用数据通道，不先给客观行业强弱，不改走其他技能



### 名称没说清

- 用户要分析个股，但名称或代码不足以确认（如「帮我看看三一」）
- 先要求用户补充股票代码或公司全称
- 用"搜索名称中包含XXX的A股股票"确认后再继续
- 补上之前不查指数、不查板块



### 数据源不可用

- 表现：MCP 工具调用报错、连接失败或返回空结果
- 处理：重试一次；仍失败则明确告知"数据源暂不可用"，并降级为仅基于用户提供信息的定性分析，或请用户稍后重试
- 若报错为 `30004 服务异常` 或 `Connection closed` 且出现在**并列批量**调用中，根因通常是并发超限而非接口宕机。本 Skill 规定按顺序逐条查询，正常执行不会触发；出现即说明调用方式跑偏，改回按顺序逐条查询。过程说明不写「串行单发」。单发仍报 `30004` 才按真不可用降级。详见 references/error-handling.md。



### 返回体过大被截断

- 表现：查询研报/舆情/全市场筛选时返回内容超出限制
- 处理：缩小范围（限定时间窗、限定条数、单只股票单次查询），把"查询N个维度"拆成多次单维度查询

**实测已超限的问法（翼答 MCP，2026-09 验证）——必须提前拆窄，不要等报错**：


| 高危问法                              | 拆窄写法                                                                                  |
| --------------------------------- | ------------------------------------------------------------------------------------- |
| `查询{股}最近一周的新闻动态`                  | 追加限制：`只要最近 8 条的标题、发布时间和来源媒体`                                                          |
| E3 风险类事件合并提问（质押+重组+诉讼+高管+再融资一口气问） | 已预拆为 E1/E2/E3a/E3b 四组；E3a 与 E3b 分开问；仍超限则再拆成单类，如单独问 `股权质押` → 改窄为 `前十大股东股权质押数量与质押比例是多少` |
| 事件/公告查询里写「定期报告」「研报」「点评」           | 会连带拉入研报库导致超限，查询措辞里**禁止**出现这三个词                                                        |


**其他已验证的数据缺陷**：

- **收盘价和日 K 线序列禁止写「最近一年」**（2026-09-22 实测）：问「{股}最近一年的每日收盘价（前复权）」返回的是 **2025-01-02~2025-12-31（243 行）**，而非截至 T 日的滚动一年（同为约 242 行，**仅凭行数无法察觉**）。后果：MA/MACD/RSI/BOLL 全部基于过期序列（实测 MA60 被算成 120.70，真实值 132.96，偏差 9.2%）。这条禁令只约束收盘价和日 K 线。公告、事件问句里的「最近一年」照抄，不要改成显式日期。正确问法与两道强制自检见 `references/data-source-queries.md` §1.3；区间一律以 `datas` 的 `时间区间` 为准。
- 指数实时行情表的 `上涨家数 / 平盘家数 / 下跌家数` 字段返回的是成交量量级的错乱数字，**不可用作市场广度**。改用「三大指数涨跌幅 vs 所属行业指数涨跌幅」做相对强弱判断。**注意区分**：批7 还会单独返回一张「上证指数／深证成指／创业板指 上涨家数·下跌家数」表（2026-09-22 实测数值合理，如上证 966/1155、深证成指 190/296、创业板指 41/56），该表为**各指数成分股口径**，可直接用于市场广度；被否掉的是"指数实时行情表"里同名字段，不是这张表。
- 估值分位数表的 `市净率` 采用 **PB(MRQ)** 口径，与行情表的 `市净率PB(LF)` 可能相差 1 倍以上（实测 26.48 vs 12.32）。报告中必须**并列标注两个口径**，禁止只写一个数配另一个口径的分位。
- **逐日估值序列的末值可能是脏值，必须用同日 PE 变动交叉校验**：2026-09-22 实测 `市净率(pb)` 由 09-21 的 27.81 单日跳至 11.81（-57.5%），同日 `市盈率(pe,ttm)` 仅由 54.19 变为 53.43（-1.4%）——两者量级完全脱节，判定为口径变动/脏值。做法：先比对"PB 单日变动 vs PE 单日变动"是否同量级，明显脱节则以前一交易日值为主、同时披露两口径与异常说明；估值分位打分只认 PE 分位（PB 仅作展示）即为此时留的余量。
- `datas` **中的数值字段可能是字符串**（含科学计数法）。解析时用 `isinstance(v,(int,float))` 过滤会**静默丢弃最新一行**，使"逐日序列 + 5/10 日聚合"方向反向（实测 5 日主力净额由真实的 -11,500 万元变成 +144,663 万元）。须强制转 float。详见 `data-source-queries.md` 返回结构小节。



### 数据缺失/接口异常

- 表现：某指标返回空值或整表缺失
- 处理：明确缺失字段与影响范围，用户确认后执行"降级分析"



### 复权口径不一致

- 常见表现：长周期涨幅与K线形态对不上
- 处理：统一使用"前复权"序列做趋势与形态判断，并在报告中注明复权方式



### 多股对比口径不一致

- 常见表现：A 用年报、B 用半年报，或A时间窗60日、B时间窗20日
- 处理：统一财报口径与K线时间窗口，再进行横向打分



### 宏观/政策信息无法验证

- 明确写出"该部分证据不足"
- 不将其作为核心结论唯一依据



## Key Principles（重要原则）

1. **覆盖范围显式化**：默认六维全覆盖；用户显式指定维度时按 Step 1 显式词表专项执行（公告 + 事件仍必查，报告中不写「安全网」）；未覆盖维度只在头部声明"未查询（按您指定的范围）"，数据缺失在对应章节写"未获取到数据（原因）"并记 `NA`，两者禁止混写
2. **先识别任务形态（单股/多股）与分析意图**
3. **先取数后判断，禁止脑补缺失数据**
4. **技术面只用当前数据源原生指标，不引入数据源外的私有字段**
5. **对比场景必须统一口径（复权方式/时间窗/报表期/指标定义）**
6. **六维模式下维度并重；专项模式下不得由单维度数据外推其他维度结论**
7. **事件必须判断是否已被价格消化，禁止线性外推**
8. **结论必须附数据依据与时间边界**
9. **始终保留风险提示与免责声明，报告以免责声明结束**
10. **合规检查必过**：仅输出客观数据与规则化描述，不给建议、不做预测、不下主观评价；判定见 `references/compliance-boundary.md`，免责声明不能替代合规改写
