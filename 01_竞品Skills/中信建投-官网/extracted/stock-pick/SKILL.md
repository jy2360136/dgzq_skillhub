# 条件选股

用因子表将用户条件匹配到合法档位，再调用脚本请求选股接口。结果以接口为准，不要编造股票或行情。

## 何时使用

用户要用**条件**筛选股票时使用，例如：

- 推荐涨跌幅大于 5% 的股票
- 人工智能且成交额大于 10 亿
- 高管增持相关股票
- 近三月跌幅超过 30% 的股票

能匹配到因子即直接筛选，不要先追加询问多项补充条件。

## 何时不使用

- 港股、美股、基金、期货、数字货币：不调用接口，说明本技能仅筛选 A 股。
- 只有「推荐好股票 / 会不会涨 / 该不该买」，无法匹配任何因子：不调用接口。需要追问，并举例可执行的筛选条件（涨跌幅大于 5%、概念板块人工智能）。
- 用户问题中既有可筛条件，又包含该买哪只、目标价、仓位时：条件部分继续筛选；买卖和预测部分予以拒绝，不在筛选结果中附加结论。

## 核心铁律（每次执行必须遵守，不可绕过）

> **分组原则**：按**执行阶段**分四组，编号只表示**时序**；**优先级由组标题承载**，不以位置暗示优先级。

### ① 门控与前置（最高优先级，先于一切取数）

1. **API Key 门控优先**：取数前确认环境变量 `CSC_SKILLHUB_API_KEY` 已配置。缺失、无效或额度耗尽时立即终止本次调用，禁止改地址、改接口、用网页搜索或训练数据顶替。提示语按「API Key 缺失时必须立即终止」原样返回。请求头为 `X-API-Key`（取该环境变量，禁止写死）与 `X-Calling-Skill-Id: stock-pick`。

### ② 范围

2. **只筛选 A 股**：只按因子条件筛选 A 股。非 A 股，以及没有可执行筛选条件的买卖和预测请求，按「何时不使用」处理。不要求用户先提供股票代码。

### ③ 数据

3. **结果以接口为准**：档位只来自因子表，`eFactor` 不得自行编写。结果只使用脚本返回的 `columns` 和 `stocks`，不换算单位，不二次查询取多数，不本地计算技术指标。接口失败时转告 `error`，不要编造数据。

### ④ 输出与合规边界（合规检查为最高优先级，与 ① 组门控同级）

4. **合规以「合规边界」为准**：给用户的文本以「合规边界」为唯一定义，逐句过三问。不输出买卖、仓位、目标价、收益预测，也不输出条件性研究判断。正常筛选结果末尾必须逐字附上「合规边界」中的免责声明，禁止同义替换、缩写、拆句或并进前文；0 只、超限、缺 API Key 不加这句，也不把这三种结果说成标的风险或无风险。

## 步骤

1. 从问句中提取选股条件，并从问句中提取「要几只」、「选几个」等数值表述。
2. **每个条件先执行** `scripts/factors.js search <关键词>`，只用搜索结果里真实存在的 `sName` + `sSubName` 调用 `pick.js`。禁止凭问句猜测 `--factor`，禁止自行编写 `eFactor`。
3. 匹配到后执行 `scripts/pick.js`。全部档位都无法匹配时，再考虑追问。
4. 用脚本 JSON 回复：按 `columns` 生成表格；有 `file` 时告诉用户完整名单在该 CSV。



### 条数

- 用户明确要 N 只：`--limit N`，不写文件。
- 未说明返回数量：不要 `--limit`（等同 `--all`）。`total > 10` 时 stdout 只有前 10 条，完整名单在 `file`。
- 单次结果上限为 3000 只。返回 `oversize: true` 时说明条件太宽，请用户加收敛条件；不要改写成「没有符合条件的股票」，也不得声称已返回全部结果。



### 追问（不要频繁触发）

能够筛选时直接筛选。每轮最多追问一次。

不要问：已经匹配到至少一档；只是未说明返回数量（此时应返回全部结果并写出文件）；筛选完成后再主动追加其他条件。

可以问一次：意图明确为选股，但没有任何档位能够匹配。

表里没有用户说的阈值/时间，但有邻近档：直接用最近的一档，并告诉用户「当前数据库没有这个因子，用最近档作为替代」。不要改动因子表中的数值来新增档位。完全无法替代时，列出 2～4 个邻近档位供用户选择。

用户仍未给出可筛选条件时，举例合法问法（涨跌幅大于 5%、概念板块人工智能），不要连续追问。

### 列

脚本已按 `sName` 去重：条件里的涨跌幅/成交额等会覆盖默认行情同名列，表头带上因子 `sSubName` 里的时间跨度（如近三月、3 日内）。

回复用脚本给的 `columns` 和 `stocks`，不要自行增加一列今日涨跌幅。若使用了替代档位，在回复中说明使用的档位。

## 脚本

本 skill 是完整的包。脚本按**自身文件位置**读取因子表，**与工作目录无关**。因此直接用技能包的绝对路径调用即可，**不要** `cd` **进包目录**——`pick.js` 默认把 CSV 写到当前工作目录，进入技能包目录会导致结果 CSV 写入技能包，从而改写技能包内容。

下文用 `$SKILL` 指代本技能包根目录（SKILL.md 所在目录）。

查因子档位：

```bash
node "$SKILL/scripts/factors.js" catalog
node "$SKILL/scripts/factors.js" search 人工智能
node "$SKILL/scripts/factors.js" get 涨跌幅/大于5%
```

选股：

```bash
node "$SKILL/scripts/pick.js" --factor 涨跌幅/大于5% --limit 3
node "$SKILL/scripts/pick.js" --factor 概念板块/人工智能 --factor 成交额/大于10亿
node "$SKILL/scripts/pick.js" --factor 涨跌幅/近三月下降30%以上 --all
```

CSV 默认写到**当前工作目录**（即用户工作区），通常无需指定；要换位置用 `--out-dir <目录>`。

没有子档的因子写成 `--factor 高管增持`。多个 `--factor` 为同时满足（AND）。

`pick.js` 输出 JSON：`ok`、`total`、`shown`、`file`（无文件则为 `null`）、`columns`、`conditions`、`stocks`。`ok` 为 false 时把 `error` 告诉用户，不要编造数据。

### 数据来源

选股数据来自 **SkillHub MCP 服务**（JSON-RPC over HTTPS `tools/call`）：

```
https://skillhub.csc108.com/api/mcp/v1/servers/csc-ecomm-ras-ypstocktools/mcp
```

工具名为 `csc-ecomm-ras-ypstocktools_tools_getStockByFactor`。请求头固定两个：


| 请求头                  | 值                      |
| -------------------- | ---------------------- |
| `X-API-Key`          | 环境变量 `CSC_SKILLHUB_API_KEY` 的值 |
| `X-Calling-Skill-Id` | `stock-pick`（固定值）      |




## API Key 缺失时必须立即终止（硬性要求）

调用选股接口前**必须**先确认运行环境中已配置环境变量 `CSC_SKILLHUB_API_KEY`。

**若运行环境中未配置** `CSC_SKILLHUB_API_KEY`**，应立即终止本次调用，不得尝试任何降级或绕过方式访问接口**（例如改换地址、改走其他接口、改用免鉴权通道、向用户索要密钥后硬编码）。此时**直接向用户原样返回以下引导提示**，不要追加解释、不要改写、不要重试：

> 您好,需要 API Key 才能使用本功能。请前往 [https://skillhub.csc108.com/finly/?channelCode=workbuddy](https://skillhub.csc108.com/finly/?channelCode=workbuddy) 申请并配置 API Key 后重试。

脚本已内置该判断，无需自行实现：

- `pick.js` 在发起请求**之前**检查 `CSC_SKILLHUB_API_KEY`。缺失或为空时，返回 `{"ok": false, "needApiKey": true, "terminated": true, ...}`，把上述提示放在 `error` 字段，并以**退出码 2** 结束——**不会发出任何网络请求**。
- API Key 已配置但无效或被作废时（网关返回 `MISSING_API_KEY` / `INVALID_API_KEY`，或 HTTP 401），同样走上述终止与提示逻辑。

因此处理方式只有一种：看到 `needApiKey: true`，就把 `error` 的原文转达给用户并停止。不要编造替代方案，不要改用其他接口，也不要要求用户提供密钥。

### 结果条数上限

单次最多返回 **3000** 只。

超出时脚本返回 `ok: false` 且带 `oversize: true`。这时要告诉用户**条件过宽**，并建议叠加收敛条件（成交额、总市值、行业板块、市盈率等），**不要当成「没有符合条件的股票」**。

## 合规边界

只根据接口返回的客观数据给出筛选结果。不能出现建议、预测等涉及证券投资咨询牌照的业务内容。免责声明不能使前文的违规内容变为合规。

给用户的每一句先过三问，命中则改写或删除：


| 测试   | 命中示例                  |
| ---- | --------------------- |
| 时间指向 | 会涨、有望、预计、目标价          |
| 宾语指向 | 建议买入、先买、加仓、减仓、仓位、止损   |
| 主体指向 | 好股票、质地好、值得关注、推荐这几只、更优 |


可以写的只有两类：

- 接口返回的代码、名称和字段。
- 「按因子表某一档筛出 N 只」。用了替代档时，点明用了哪一档。

不要出现：推荐、建议买入、持有、建仓、减仓、止损、目标价、值得、看好、有望、预计。

引导用户收窄条件时，「建议叠加成交额等条件」可以保留。此处指筛选条件，不属于买卖建议。

名单按接口返回顺序展示，不是优劣排序。不要写「优先、首选、更值得、先看这只」。用户要 N 只时，只说明「按指定条数展示前 N 只」。

正常筛选回复的最后原样附上这句，一个字不改。这句豁免三问和禁用词，不得为了避开「推荐」「建议」「涨跌」而改写：

> 本智能选股工具仅根据您设置的条件自动筛选个股，数据来源于第三方公开信息，仅作信息参考，不构成个股推荐、投资建议或交易指导；工具基于历史数据筛选，存在算法、数据滞后等局限性，不对标的未来涨跌做预判，筛选结果不可直接作为交易依据，所有投资决策由您独立作出，投资风险自行承担。投资有风险，入市需谨慎。

0 只、超限、缺 API Key 的回复不加这句。

## 回复

- 顺序：筛选条件（含替代档）→ 表格 → 「共 N 只」→ 顺序说明 → 原样附上「合规边界」中的免责声明。有文件则给路径，并说明对话里只展示前 10 只。
- 0 只：说明没有符合条件的股票。不加免责句。
- 超限（`oversize: true`）：说明条件太宽导致超出网关上限，给出收窄方向，不要报成 0 只。不加免责句。
- 缺 API Key、接口失败：按上文错误口径原样转告，不加免责句，不要编造数据。
- 用词和名单顺序遵守「合规边界」。



### 出口检查

发出前核对：

- 没有三问命中的句子。
- 没有禁用词（「建议叠加…条件」除外）。
- 没有将名单表述为排序或优选。
- 正常结果末尾与「合规边界」中的免责声明逐字一致，不是另写一句类似的风险提示。

## 例子

用户：帮我推荐 3 只涨跌幅大于 5% 的股票  
→ 先 `search 涨跌幅`，确认有 `涨跌幅/大于5%` 后再 `--factor 涨跌幅/大于5% --limit 3`，只展示 3 只。表题写「涨跌幅大于 5% 的筛选结果」，不写「推荐如下」。

用户：筛选涨跌幅大于 5% 的股票  
→ 先 `search 涨跌幅`，再 `--factor 涨跌幅/大于5%`（全量）。超过 10 只则表 10 行 + CSV。

用户：近三月跌幅超过 30%  
→ 先 `search 涨跌幅` 或 `search 近三月`，匹配 `涨跌幅/近三月下降30%以上`。涨跌幅列应是近三月数据，不要另行增加今日涨跌幅列。

用户：帮我推荐 3 只成交量小于 2000 手且市盈率大于 50 的股票  
→ 先 `search 成交量`、`search 市盈率`。市盈率有 `大于50`；成交量没有「小于 2000 手」，最近档是 `小于3000手`。用 `--factor 成交量/小于3000手 --factor 市盈率/大于50 --limit 3`，并告诉用户：当前数据库没有这个因子，用最近档作为替代（成交量/小于3000手）。

用户：推荐点好股票  
→ 追问一次，举例可筛选的具体条件，此时不要调用接口。

用户：筛一下概念板块人工智能的股票  
→ 先 `search 人工智能` 匹配 `概念板块/人工智能`。若命中超过 3000 只，脚本返回 `oversize: true`。此时告知：条件过宽、超出单次 3000 只上限，建议叠加收敛条件（如 `--factor 成交额/大于10亿`）。**不要**表述为「没有符合条件的股票」。

用户：这 3 只里哪只更好  
→ 表格已经给出则不再调用接口。说明只提供筛选结果，不比较买卖优先级。

用户：筛几只港股人工智能  
→ 不调用接口，说明本技能仅筛选 A 股。
