# 市场事件催化分析规则

## 1. 边界

1. 只列已发生与已公布事件。默认窗口为近 2 周，用户指定窗口时以用户为准。
2. 不查询、不使用“未来日程”。本数据源对该问法返回过往或混杂信息。
3. 不臆测未宣布的政策。禁止“预计降准”“将出台某政策”。
4. 返回内容里的旧闻只可标为“历史先例”，不得列入本期清单。逐条核对日期。
5. 传闻不得作为已确认催化。

## 2. 事件结构

每条事件至少记录：标题、首次发布时间、最新进展、主体、动作、影响对象、证据来源、证据等级、影响方向（仅描述事件文本中的既定动作，不外推后市）、持续性依据、催化阶段、市场反应、失效条件。证据等级 S、A、B 只留在内部。报告写日期和来源，不写字母。

事件阶段：新发生、发展中、升级中、稳定、结束、反转。阶段必须有事实依据。没有后续事实时停在“新发生”，不写成“升级中”。

## 3. 事件来源层级

优先使用监管文件、政府和行业协会、公司公告、定期报告，再使用权威媒体。研报只作为引用，必须有机构名和日期；数据源没有该研报时不得编造。同一事件有多来源时，以最高层级为准并注明。

## 4. 传导链

```text
事件事实
→ 直接影响对象
→ 产业或政策传导
→ 收入、成本、供需或估值口径上的可能影响
→ 相关行业或概念的已发生市场表现
→ 强化条件与失效条件
```

必须区分直接、间接和可能相关。不能把整个概念板块都视为受益对象。传导链中的“可能影响”是条件句，不是方向预测。

公司名可以作为事件事实主体出现。不得对该公司给出走势、评价或结论。

## 5. 催化强度

| 状态 | 条件 |
|---|---|
| 事实催化 | 高等级来源确认，影响对象和机制清晰 |
| 发展中催化 | 事件已确认，影响规模或持续性仍需核验 |
| 预期催化 | 市场预期或政策方向已见诸可引用来源，尚未形成已确认结果；必须标注来源和“待观察” |
| 交易性催化 | 主要看到涨幅或资金，基本面传导不足 |
| 失效/反转 | 关键条件未兑现，或出现反向事实 |
| 证据不足 | 来源、日期或影响对象有一项无法核验 |

## 6. 市场验证

至少检查可得的项：

- 事件发生日之后，相关概念或行业指数的区间表现；
- 成交或资金是否持续，还是只有事件日；
- 市场表现与传导方向是否一致。

取不到的项内部记 `NA`。报告写「未获取到」，并点名缺的是哪一项。市场上涨只能说明交易反馈，不能单独证明事件的实质影响。

## 7. 与主线的关系

事件点名的板块可以进入主线候选池。进入候选池不等于主线。催化状态不能替代 `market-mainline-rules.md` 的五项条件。本次未覆盖主线时，这些板块只用于催化的市场验证，不另开主线章。

## 8. 事件结论模板

```text
事件事实：……（日期、来源。不写证据等级字母）
影响路径：可能通过……影响……
市场验证：……（取不到时写「未获取到」，并点名缺哪一项。不写 NA）
当前判断：事实催化 / 发展中催化 / 预期催化 / 交易性催化 / 失效/反转 / 证据不足
强化条件：……
失效条件：……
置信度：高 / 中 / 低
```
