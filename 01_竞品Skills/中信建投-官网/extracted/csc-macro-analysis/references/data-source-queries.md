# 当前数据源查询手册（翼答版）

翼答是问答智能体。问句用口语，返回是散文加动态组件。结构化组件优先。实测禁止的问法不要换近义词再试。

## 调用

```
python3 references/mcp_skillhub_call.py \
  --server csc-ecomm-ra-llmtools-yida \
  --slug csc-macro-analysis \
  --question "<口语化问题>"
```

串行单发。单条不超过 600 字。全量不超过 14 次，资金点名不超过 6 条。

## 〇、用户指定历史日期窗口时（如「复盘 9 月 24 日」）

本数据源的默认问法锚定「当前」，返回的窗口是最近一周/最近一个月。**用户指定的基准日若是过去的某个交易日，在问句里直接写出该日期区间即可把窗口对齐**，不要用「最近一周」的结果去替代（那会拿到以取数当日为终点的窗口）。

| 用途 | 写法 |
|---|---|
| 概念排名 | `9月18日到9月24日涨幅居前的A股概念板块有哪些` → 组件键 `涨跌幅[20260918-20260924]` |
| 候选双窗口点名 | `885955.TI、885769.TI、885994.TI和885937.TI从9月18日到9月24日、从8月25日到9月24日的涨跌幅分别是多少呀` → `bar3` 8 行 |
| 资金逐日点名 | `885955.TI、885769.TI、885994.TI和886043.TI从9月18日到9月24日每天的主力资金净流入分别是多少呀` → `timeBar` 20 行（4×5） |
| 事件 | `2026年9月10日到9月24日A股市场有哪些重要的政策和事件`（三条问句都带同一区间与**完整年份**） |
| 风格 | **仍走 §一 的日线序列问句**，拿到后按用户基准日截断自算 |

日期区间的具体起止由用户基准日推定（**推定规则，两处样例见下，一律以组件返回的 `时间区间` 为准，逐个核对**；写法细节见 `env-observations.md` §三十三）：

- **近一周 = 基准日往前 6 个自然日（7 天窗）**。样例：基准日 09-24 → `0918-0924`；基准日 09-28 → `0922-0928`。
- **近一月 = 基准日往前 30 个自然日**，起点若落在非交易日则取之前最近的交易日。样例：基准日 09-24 → `0825-0924`；基准日 09-28 → `0828-0928`。
- ⚠️ 不要按「前推 4 个交易日」推算近一周——遇到休市日会算错一天（09-28 前推 4 个交易日得 09-21，而数据源给的是 09-22）。
- ⚠️ **基准日往前 7 个自然日内含连续休市（春节、国庆等长假）时，「最近一周」问法退化为单日窗**：组件键呈 `涨跌幅[YYYYMMDD]`（单日）而非 `涨跌幅[YYYYMMDD-YYYYMMDD]`（区间）。**长假后首个交易日不用默认问法**，直接写显式区间取近 5 个交易日（基准日往前 4 个交易日）。核对方法：看组件键是单日还是区间，**单日键不得当作周窗排名使用**。「最近一个月」默认问法不受影响。

**资金点名的窗口与概念排名不同，固定写「基准日前推 4 个交易日 到 基准日」（= 近 5 个交易日）**，因为 `research/market-mainline-rules.md` §4 要求的是近 5 日资金。跟随概念排名的 7 天窗会漏掉第一个交易日，多日净额会由正转负（2026-09-28 样例：4 日窗下 4 只候选净额全为负，补上 09-21 后三只转正）。

**用户说「上周」时是日历周窗口，不是「末 5 行」**：取落在该日历周内的交易日行（实测：2026-09-21 至 09-25 内只有 09-21、09-22、09-23、09-24 四行，09-25 无交易数据），窗口写成「上周首个交易日的前一交易日收盘 → 上周最后交易日收盘」，并在报告第一节写明实际交易日数。**不要用「末 5 行」顶替该周窗口**——两者会差一个交易日（实测：末 5 行含 09-18，科创50 与中证1000 的相对收益因此由负转正）。风格判定时把「末 5 行」窗口一并列出；两个窗口方向不一致时，按窗口方向不一致处理，不用其一覆盖其二。

窗口口径两套并存，**不要互相替换**：风格按「末 N 行累计（起算收盘日 → 末日）」，概念按组件自带区间（含首日）。两者的相对收益各自用**同区间**的沪深300相减。

## 一、风格

| # | 问法 |
|---|---|
| 1 | `最近一周和最近一个月，上证50指数、中证1000指数相对沪深300指数的涨跌幅分别是多少` |
| 2 | `最近一周和最近一个月，中证红利指数、科创50指数相对沪深300指数的涨跌幅分别是多少` |
| 3 | `最近三个月上证50指数、中证1000指数、中证红利指数、科创50指数和沪深300指数的涨跌幅分别是多少` |
| 4 | `今天上证50指数、中证1000指数、中证红利指数、科创50指数的涨跌幅分别是多少` |
| 5 | 相邻两日对比（用户指定「今天和昨天」时）：用第 3 条的日线序列即可，**末行是最近交易日，与上一行直接对比**，不必再发第 4 条。方向：先看序列末两行的 `时间区间` 是否连续，休市日会缺行，缺行时以上一交易日为基准并在第一节写明 |

第 3、4 条若合并后报错，拆成两条同类问句，每条最多三只指数。不要问中证2000、国证成长、国证价值。

**粒度核对（合并问句必做）**：合并问句返回的每个组件都要打印「行数 + 末行 `时间区间`」，核对粒度与本问句要求一致（日线 = 8 位纯数字日期键 + `涨跌幅:前复权`）。**沪深300 的日线末行必须等于序列末日**；出现分时粒度（`时间区间` 形如 `YYYYMMDD HH:MM:SS`、按 `分时涨跌幅:前复权` 取值）或行数虽多但只覆盖单一交易日，即视为该组件不可用，**补发一条同名单指数问句**（`最近三个月沪深300指数每个交易日的涨跌幅分别是多少`）后再统一自算。不要用行数判断序列是否完整，也不要把分时值当日线用。

> ⚠️ **第 3 条必须加「每个交易日的」**：写成 `最近三个月……五只指数每个交易日的涨跌幅分别是多少`。不加时返回 `bar3` 的 5 行**区间汇总值**（实测区间 20260625-20260924，66 个交易日，长于 60 日），与末 60 行累计口径不一致（实测上证50 约60日超额 6.76 vs 5.37）。加了「每个交易日的」才返回日线序列，可自算全部窗口。约 60 日一律以日线自算为准，不采用区间汇总值。

## 二、主线

| # | 问法 |
|---|---|
| 1 | `最近一周涨幅居前的A股概念板块有哪些`（返回业务错误时改用口语变体 `最近一周A股哪些概念板块涨幅靠前`） |
| 2 | `最近一个月涨幅居前的A股概念板块有哪些`（口语变体 `最近一个月A股哪些概念板块涨幅靠前`） |
| 3 | 候选板块双窗口收益（候选池形成后，按指数代码点名，一次最多 4 只）：`886033.TI、885959.TI、886043.TI和885955.TI最近一周和最近一个月的涨跌幅分别是多少呀` |
| 4 | 相邻两日对比（板块层，用户指定「今天和昨天」时）：`885955.TI、885994.TI、885937.TI和885860.TI最近5个交易日每个交易日的涨跌幅分别是多少`（返回逐日序列 `timeChart`，与第 3 条的区间组件 `timeBar` 是两个组件，不要混用；加 `--max-rows 0`） |

第 3 条是必需的：排名问句每次只回一个窗口，单靠排名无法判断候选在另一窗口的方向，主线候选条件 1 要求两个窗口的相对收益同时为正。同一板块在排名组件与点名组件中的数值略有差异，报告中以点名组件为准，不标注两处差异。

候选池刚形成、手上还没有指数代码时，可以先用概念名点名**涨跌幅**（如 `人形机器人概念指数最近一周和最近一个月的涨跌幅分别是多少`），该问法会返回对应指数并附日线序列；拿到代码后仍按代码点名。**只有对资金流**才禁止按概念名点名（会退化为个股排行，见 §三）。

禁用申万一级行业涨跌幅排名。禁用任何“哪些个股”问法。

### 二之一、脚本调用纪律

按日线自算窗口收益时，必须加 `--max-rows 0`。默认值只输出序列头部若干行，会丢掉最近窗口，导致无法自算 5 日与 20 日。

## 三、资金序列

只给进入候选、且两个窗口都靠前的主题点名，最多 6 条。用板块指数代码或同花顺行业指数，不用概念名。

```
885811.TI最近5个交易日主力资金净流入是多少
```

同一条问句可并列多个指数代码（实测 4 只可行），返回组件按代码分组：

```
886043.TI、885959.TI、885955.TI和885769.TI最近5个交易日主力资金净流入分别是多少
```

**必须加 `--max-rows 0`。** 多只代码并列时总行数是「代码数 × 交易日数」，默认 50 行会截断成头部若干天，**看起来像数据滞后**（实测：2 只代码各 30 天 = 60 行，默认只留前 50 行，序列止于上一周中段），实际是输出被截断。

**用户指定历史基准日时，把「最近5个交易日」改写成具体日期区间（6 个自然日 / 5 个交易日），并核对每只的 `时间区间` 是否覆盖这 5 日。** 该区间与概念排名的 7 天窗不同，不要混用（见 §〇）。

取到序列后核对每只的 `时间区间` 起止：同一问句不同调用可能落到不同窗口（实测出现过 0911–0917 与 0918–0924 两种），**必须与本次涨跌幅窗口对齐后再计算**。

按概念名点名（如“某概念板块最近5个交易日主力资金净流入”）会返回个股排行，整条作废。禁止“哪些板块主力资金净流入最多”。

## 四、事件

| # | 问法 |
|---|---|
| 1 | `2026年9月10日到9月24日A股市场有哪些重要的政策和事件` |
| 2 | `2026年9月10日到9月24日有哪些重要的产业政策或者产业动态` |
| 3 | `2026年9月10日到9月24日A股市场有哪些风险事件` |

**日期必须写全「年+月+日」。** 只写「9月10日到9月24日」时，回答会把年月自行改写（如改写成「2024年9月10日至9月24日」）并返回跨年旧闻；补上「2026年」后该类混入显著减少。

全量、只问主线、只问催化：三条都发。只问风格：三条都不发。只问主线时，事件结果只进入主线证据，不展开催化章。不要问未来日程。

### 五之一、行业定向补查（可选，占用总次数额度）

上面三条是通用问句，返回的条目常与本次候选池毫无关系，导致主线条件 5 只能写「未获取到」。候选池形成后，可对**最靠前的方向**各补一条行业定向问句，把「未核验」变成「已核验但不成立」或「已核验成立」：

| # | 问法 | 用途 |
|---|---|---|
| 1 | `9月10日到9月24日医药生物行业有哪些重要的政策或者事件` | 核验医药方向候选（重组蛋白、细胞免疫治疗、CRO 等）的事件逻辑 |
| 2 | `9月18日到9月24日创新药或者生物医药领域有哪些重要的产业动态` | 同上，粒度更偏产业动态 |
| 3 | `《{文件名}》是哪个部门在什么时候印发的，文号是什么` | 第 1、2 条的条目若左右窗口归属，必须用它定日期 |

纪律：

- 第 3 条**只问一件事**，一次核验一个文件；**首轮散文里的日期不得直接采用**（实测首轮把 08-28 印发写成 09-18）。
- **泛问整条无日期时，先换「更短的行业名」重问一次，再考虑逐条追问日期**。实测（2026-09-30）：`房地产或者住房租赁领域有哪些重要的政策或者事件` 返回的公积金、城市更新、司法案例条目**全部无日期**；换成 `房地产行业有哪些重要的政策或者事件` 一次返回 6 条以上带日期条目（09-18 住建部发布会、09-20 公积金条例实施、09-23 北京销售制度改革、09-28 国常会、09-29 财政部贴息通知）。一条问句的成本换回多条可用条目，优于对单条反复追问。
- **追问核验出的日期若落在本期窗口之外**，该条按「历史先例」处理，**不得计入条件 5**（实测：医药工业类规划的印发日核验为窗口外日期）。
- 第 3 条适用于**规划类文件**：「十五五」类规划在行业泛问里往往只回文件名、不带印发日（整条不可用），**点名文件追问印发部门 + 日期 + 文号才拿得到可用条目**（实测：《出版业发展“十五五”规划》泛问无日期，单条追问命中 `2026-09-16，国新出发〔2026〕8号`）。→ 定向补查若返回无日期的规划名，**对它补一条第 3 条问句**，不要直接写「未获取到」。
- **发布日类字段可能根本取不到**：追问「是哪个部门在什么时候发布的」时，返回可能只给**实施日期**或**标准号**，不给发布日（实测：脑机接口医疗器械标准只回 `2027-09-01 实施` + `YY/T 2029-2026`；大行增资 3600 亿只回资金构成、不回公布日）。**追问一次仍无发布日即判「日期不可核验」并放弃该条，不再追问、不换问法**；核验次数要在 14 次额度里按「可能失败」预留。
- 三条通用事件问句 + 定向补查的总数，仍计入「全量不超过 14 次」的额度。
- 定向补查点名的行业必须**来自本次候选池**，不得为不在候选池的方向补查。

## 五、解析

1. 字段名取 `datas` 行的键，不读 `columns[].label`。
2. `rich_text` 只拼接，不按文本去重。
3. 组件 `total_rows ≤ 1` 视为不可得。
4. 资金流常以元返回，报告写成亿元。
5. 标的以返回体代码和名称为准，不以 NLU 为准。
6. 出现 `股票简称`、`股票代码` 或 `股票名称`，整条作废。
7. 区间起止与问句对齐，丢首日的累计值不用。组件与散文冲突时，窗口对齐后以组件为准，不在报告中标注。
8. ⚠️ **先落盘再解析，不要用 `head -c` / `tail` 截断 stdout**。日线序列按旧→新排序，`--max-rows 0` 的全量 JSON 常常几万字符；截断 stdout 会丢掉**序列尾部（即最近交易日）**，看起来像数据滞后。正确做法是先 `> /tmp/xx.json` 落盘，再用一段 Python 只打印聚合结果与尾段若干行。
9. ⚠️ **散文里的「相对涨跌幅」不可用**：问「A、B 相对沪深300 的涨跌幅」时，`rich_text` 常把沪深300 **自身**的日涨幅当作「沪深300 相对沪深300」输出，其余数值也不是减出来的超额。相对收益一律用组件数值自算（基准与各风格指数同一窗口相减），散文只作辅助。

## 六、失败

| 现象 | 处置 |
|---|---|
| `30004` | 改得更口语，重试 1 次；仍失败则该项不可得 |
| 空组件或散文写暂无 | 该项不可得 |
| 返回了另一个标的 | 不用 |
| 限流 | 短退避后重试 1 次 |
| 含个股字段 | 整条作废 |

鉴权失败和额度耗尽不在这里降级，直接终止。见 `error-handling.md`。

## 七、默认顺序

按本次范围跳过未覆盖的问句：风格问句 → 概念排名 → 事件 → 资金点名。资金点名必须发生在主线候选池形成之后。同一条消息里不要并列多条取数。
