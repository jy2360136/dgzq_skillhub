# 错误处理指南

本文档提供个股分析过程中常见异常的具体示例和解决方案。

**数据源**：翼答金融数据查询MCP，经 `references/mcp_skillhub_call.py` 直连 SkillHub 端点取数（脚本内部调用工具底层名 `csc-ecomm-ra-llmtools-yida_tools_yida`，不依赖可用工具列表/连接器）。
翼答走标准 MCP 通道，**鉴权经 SkillHub**：需在运行环境配置 `CSC_SKILLHUB_API_KEY`，调用时带 `X-API-Key`（取 `$CSC_SKILLHUB_API_KEY`）与 `X-Calling-Skill-Id` 两个请求头；未配置 / Key 无效 / 额度耗尽即终止调用（见下方鉴权纪律），无需用户安装 CLI。
**但翼答有频率限制（429 限流）与后端过载（504）**，属环境层现象，具体错误码/超时/退避秒数见 `references/data-source-resilience.md`（标注"随实现变化即作废"，不得作为架构强制流程）。

> **架构层纪律（主流程只认这些）**：
> - 单次查询失败 → **重试 1 次（指原句重发）** → 仍失败 → 显式降级并标注"未获取到数据（原因）"
> - **「重试 1 次」适用范围**：仅限查询失败（报错/超时/空）。新闻/公告/事件的 A 类超限走 §10.2「拆窄重问（至多 2 次）」，属改问法、不计入本项重试次数。
> - **串行已天然形成间隔，不插入固定 sleep**；退避仅在真实命中限流（429）时由环境层建议触发
> - 失败不再用"多等几秒再试"的硬等待去赌成功，超时窗口由环境层定

> ⚠️ **鉴权与配额类错误不走本文件的降级通道**：凡出现以下任一情况，**立即终止本次调用**，原样返回 SKILL.md「API Key 门控」的引导提示并补一句具体原因；**禁止**重试、禁止换问法、禁止改用 web_search / HTTP / 训练数据绕过：
> - 未配置环境变量 `CSC_SKILLHUB_API_KEY`
> - 鉴权失败：401 / 403 / `MISSING_API_KEY` / `INVALID_API_KEY` / `mcp-auth missing client identity`
> - 配额耗尽：429 / quota exceeded（Key 由用户各自申请，**有额度限制**，用完即止）
>
> 走降级通道会把"缺 Key / 没额度"伪装成"未获取到数据"，属于违规。额度恢复或换 Key 后重跑即可，不要在本次调用里硬凑结论。
> 正常取数调用须带 `X-API-Key`（取 `$CSC_SKILLHUB_API_KEY`）与 `X-Calling-Skill-Id` 两个请求头（取值见 `data-source-config.md`）。

## 1. 问错对象，或名称没说清

### 1.1 问错对象

**场景**：用户未点名 A 股，问的是大盘、指数、市场风格、行业比较、板块轮动、入场或资金配置。

**处理方式**：按 SKILL.md 铁律对象门控立即结束。原样返回固定两句，不查 Key，不探测，不取数，不改走其他技能。不要改成请用户补代码。

### 1.2 名称没说清

**场景**：用户要分析个股，但未提供可确认的股票代码或公司名称。

**处理方式**：
- 先要求用户补充股票代码或公司全称
- 使用搜索查询辅助确认后再继续
- 补上之前不查指数、不查板块

**查询示例**：

```
question: 搜索名称中包含"茅台"的A股股票，返回股票名称和代码
```

**示例对话**：

```
用户: 帮我分析一下茅台
Agent: 已找到匹配股票：贵州茅台(600519)，确认分析此标的吗？
```

## 2. MCP 未连通 / 工具不可用

**表现**：

```
# 形态一：脚本调用失败 / 端点不可达
HTTPError / URLError: <endpoint> 连接失败
Error: connect ECONNREFUSED / NameResolutionError

# 形态二：工具未找到（脚本返回 error 或 HTTP 404）
error: method not found / 404 Not Found
```

> ⚠️ **按模式识别，不要按字面量匹配**：端点 / server 名是 `references/data-source-config.md` 中的当前值，换环境会变；判断依据只认关键特征——`连接失败` / `ECONNREFUSED`（端点不可达）与 `404` / `method not found`（工具没挂上）。看到具体名字时与 config 当前值对照即可，不要把它当成固定字符串写进流程。

**原因**：
- `CSC_SKILLHUB_API_KEY` 未配置或无效（门控应已拦下，若漏网此处兜底）
- 网络不可达 / SkillHub 域名无法访问
- 端点 / server 名与 config 不一致（换环境未同步）

**解决方案**：

1. 重试一次（瞬时网络问题可能自愈）
2. 仍失败时，明确告知用户：**"当前数据源（翼答金融数据查询MCP）当前不可用，本次分析无法取数。"**
3. 提供降级路径：
   - 若用户已提供部分数据（截图、报告、手输数值），基于用户提供的数据做**明确定性分析**，并在报告头部显著标注"数据来源：用户提供，未经数据源校验"
   - 引导用户确认 `CSC_SKILLHUB_API_KEY` 已正确配置且 Key 有效、本机网络可访问 `skillhub.csc108.com`（详见 `references/data-source-config.md` §二·A）
4. **禁止**编造数值填充空白

## 3. 返回体过大被截断 / rich_text 超长

**表现**（翼答常见）：

```
新闻/公告/事件类 rich_text 返回体极大（可达数十万字符），触发 token 上限或解析超时
result (372,021 characters) exceeds maximum allowed tokens
```

**触发场景**（最常见）：
- 一次查询要多个维度（如"公告+新闻+研报+评级"同时问）
- 查询"最近一个月的研报"或"最近一周的新闻"不加条数限制
- 全市场条件筛选

**解决方案**：

1. 若结果已落盘，从落盘文件提取需要的 `result_page` 组件或 `rich_text` 片段
2. 后续查询**拆窄**（按 `result_page` / `rich_text` 两类分别处理）：

| 错误做法 | 正确做法 |
| --- | --- |
| 查询公告、新闻和研报评级 | 查询最近3条研报的标题、机构与结论 |
| 查询最近一个月的新闻 | 查询最近一周的新闻，只要5条标题+发布时间+来源 |
| 查询所有财务数据 | 分组问：ROE / 毛利率净利率 / 营收同比 / 净利同比 / 每股现金流 |
| 板块内所有股票 | 查询该股票在所属行业中的相对位置 |

3. 翼答**没有** `api_name` 表名概念，不要按表名拼 query；直接用自然语言说要什么指标

## 4. 数据缺失 / 字段为空

**表现**：某指标返回 `None`、空字符串，或整张 `result_page` 缺失；`rich_text` 为空或无关

**常见原因**：
- 该股票确实无此数据（如新股无250日均线、无历史估值分位）
- 该标的属于特殊板块（次新股、退市整理期）
- 数据源尚未更新当日数据

**解决方案**：

1. 先确认是否**合理缺失**（新股上市不足250个交易日 → MA250 必然为空）
2. 明确缺失字段与影响范围
3. 执行"降级分析"并在报告中标注

**降级分析示例**：

```markdown
由于该标的上市不足一年，MA250 与近三年估值分位暂无数据，本次分析将：
- 技术面：以 MA5/MA10/MA20/MA60 为主，长期趋势维度标注"数据不足"
- 估值：仅给绝对估值水平（PE(TTM)），不判断历史分位高低
- 综合评分：缺失维度按 `scoring.md` §3 记 **NA**（不记 0 分、权重从总分基数剔除），并在"未评分项"标注"未获取到数据"；NA 之前必须已完成拆窄重问（scoring.md §3.1 防偷懒纪律）
```

## 5. 区间行情接口不精确

**场景**：查询"最近 N 个交易日涨跌幅"，返回的行数与预期不符

**表现**：问 5/10/20/60 日，可能返回近似区间而非精确 N 日

**原因**：翼答对自然语言中的"N日"解析为近似日期范围，**不保证精确交易日数**

**解决方案**：

需要**精确 N 日涨跌幅**时，改从日行情序列自行计算：

```
N日涨跌幅 =（最新收盘价 / N个交易日前收盘价 − 1）× 100
```

即先查询：

```
question: 查询{名称}{代码}从{约一年前的 YYYY年M月D日}到{最新交易日的 YYYY年M月D日}的日K线数据，包含开盘价、最高价、最低价、收盘价、成交量（前复权）
```

再从返回的 `result_page` 取所需日期的 `收盘价:前复权` 计算。禁止用「最近 250 个交易日」或「最近一年」代替显式日期（见 `data-source-queries.md` §1.3）。

> 聚合类指标（振幅、最大回撤、涨跌天数、涨停跌停天数）不依赖精确天数，可直接用翼答区间行情结果。

## 6. 复权口径不一致

**表现**：长周期涨跌幅与K线形态对不上；同一 query 返回 `前复权` 与 `不复权` 两类列

**原因**：日行情序列可带不同复权后缀（如 `收盘价:前复权` vs `收盘价:不复权`），混用导致计算失真

**解决方案**：

1. 分析中**统一固定为前复权**序列，并在报告"数据来源"处注明"行情为前复权"
2. 计算区间涨跌幅时，分子分母必须来自**同一复权方式**的列
3. 若当日行情为"不复权"（实时价格），与历史前复权序列混用时须明确标注

## 7. 多股对比口径不一致

**常见表现**：
- A 用年报、B 用半年报
- A 时间窗 60 日、B 时间窗 20 日
- A 前复权、B 不复权

**解决方案**：

1. 逐只查询，但**锁定同一报告期与同一时间窗**
2. 报告期不一致时（如 A 已出半年报、B 只有一季报），必须标注"报告期不可比"，并优先使用**同比指标**横比（同比已消除季节性）
3. 估值对比优先用**历史分位**（已归一化，可直接横比）

## 8. 行业/政策信息无法验证

**场景**：行业政策、监管导向等定性信息无法通过数据源稳定获取

**处理方式**：
- 明确写出"该部分证据不足"
- 不将其作为核心结论唯一依据
- 引导用户提供具体信息来源

**示例输出**：

```markdown
### 行业政策分析

**数据状态**：外部政策信息暂无法验证

**处理方式**：
- 建议用户通过巨潮资讯、官方公告确认
- 本分析暂不将政策因素纳入评分依据，对应维度已标注数据缺口
- 行业景气判断改为基于行业指数行情（工程机械主题 931752 近10日累计 +X%）
```

## 9. 新闻/舆情命中无关内容

**场景**：查询某股票的新闻动态时，返回大量行业新闻或关键词误命中的其他公司新闻（翼答 `rich_text` 尤甚）

**处理方式**：
- 逐条核对新闻标题与正文是否**确实涉及目标标的**，剔除无关条目
- 引用研报时**必须注明撰写机构与撰写时间**，不得笼统说"机构认为"
- 舆情原文含 HTML 标签，引用前清洗

## 10. 新闻 / 公告 / 事件取数失败（覆盖集合内维度的降级规则）

**场景**：新闻、公告、事件三类查询结果为空、报错或明显不完整（翼答下这三类通常走 `rich_text`）

> ⚠️ **公告与事件是安全网，任何模式必查；新闻仅在六维模式必查**（铁律第 4 条：覆盖范围显式化）。三者**均不允许静默跳过**——覆盖范围内取不到按本节降级；按用户范围未查询的维度记 `NOT_COVERED`（措辞"未查询（按用户指定范围）"），**不得记 NA**。

### 10.1 先判别失败类型（顺序不可颠倒）

翼答三类数据的典型失败模式共 4 种，**处理方式不同**，误判会直接导致结论失真：

| 类型 | 表现 | 是否算"缺失" | 处理方式 |
| --- | --- | --- | --- |
| **A. 返回体过大被拒** | 工具直接报错 `exceeds maximum allowed tokens`（高关注度个股的新闻/研报查询常见） | ❌ **不算缺失** | **必须拆窄重问**（收敛问法），见 10.2；重问成功即视为已覆盖 |
| **B. 查询成功但内容为空** | `result_page` 有组件但 `datas` 空，`rich_text` 为空或"暂无数据"（如某标的从未做过股权激励） | ❌ 不算缺失 | 记录为"未发现"，属**有效结论**，不是数据缺口 |
| **C. 查询成功但全是噪声** | `rich_text` 返回条目均与本标的无实质关联（常见于冷门股：正文仅在名单里提了一句） | ⚠️ **剔除后剩余 0 条才算缺失** | 逐条核对后写"已检索但未发现涉及本标的的有效新闻" |
| **D. 接口真失败** | 报错、超时、返回空结果，且拆窄重问后仍失败 | ✅ 才算缺失 | 走 10.3 显式降级 |

> **关键**：A 类最易误判。它高发于**大市值、高关注度**标的——恰恰是最容易拿到完整数据的那一批。把 A 类当成缺失，会造成系统性的评分压低。

### 10.2 A 类拆窄重问（收敛，至多 2 次即停）

> ⚠️ **本机制豁免于「失败重试 1 次」纪律**：A 类是查询**已成功返回**、但响应体过大被截断；修复手段是**换窄问法重问（提出一个更小、更具体的新问题）**，不是重发原句。因此这里的"至多 2 次"指**收窄重问的次数**，不属于 § 架构层纪律里的"原句重发 1 次"。它专门用于防止大市值/高关注度股因一次超限被误判成"缺失"而系统性压低综合评分。

按序收敛，成功即停（具体秒数/次数属环境层，见 `data-source-resilience.md`）：

1. 限定条数：`查询{名称}{代码}最近一周的新闻，只要3条标题和发布时间`（不要"新闻原文内容"）
2. 缩短时间窗：`最近三天` → `最近一天`
3. 拆维度：把"公告+事件+回购+增减持"拆成单次只问一类

**提问避坑**：事件/公告查询中**不要出现"定期报告""研报""点评"等词**——会连带拉入研报库（单表可达数万字符），直接触发超限。

### 10.3 D 类显式降级

- 报告中对应位置写：`未获取到数据（原因：接口报错 / 返回为空 / 超出返回限制且拆窄重问失败）`
- 在**风险提示**中增补一条：`本次分析未覆盖XX维度，存在信息盲区`
- 按 10.4 处理评分与信息盲区标注

### 10.4 缺失维度的评分处理

> ⚠️ 评级体系已废除。缺失维度**不再记 0 分**（旧口径已废除），改为按 `scoring.md` §3 记 **NA**：该维度权重从总分基数剔除，总分按 `scoring.md` §3.2 计算，同时输出覆盖率与未评分项。**NA 的前置门槛**：必须已完成本文件 10.2 的拆窄重问，重问仍失败才可记 NA；跳过重试直接 NA 按执行不合格处理。
> ⚠️ **按用户指定范围未查询的维度记 `NOT_COVERED`，不是 `NA`**（措辞"未查询（按用户指定范围）"）；专项模式不出总分，见 `scoring.md` §10。

| 缺失情况 | 评分处理 | 附加标注 |
| --- | --- | --- |
| **新闻未覆盖（专项模式）** | 记 `NOT_COVERED`（**不计 NA**、不进覆盖率分子） | 措辞"未查询（按用户指定范围）"，**不得写"无新闻"** |
| 仅**新闻**缺失或无效（六维模式） | 事件与消息面维度内缺失子项记 NA，维度内按可得子项归一化 | 风险提示说明"消息面未覆盖" |
| **公告**缺失 | 公告相关子项记 NA | 标注"未获取到数据（原因）" |
| **事件**缺失 | 事件相关子项记 NA | 标注"未获取到数据（原因）" |
| **公告 + 事件**同时缺失 | 两类子项均记 NA | 核心结论显著位置标注"存在重大信息盲区" |
| 三类全缺 | 只出数据快照 | 明确"本次不具备完整评分条件"，不输出总分 |

> 单类子项为空（如"未做股权激励"）**不适用**本表，那是有效结论。
>
> ⚠️ **未覆盖 ≠ 缺失**：`NOT_COVERED` 是"按用户指定范围没查"，`NA` 是"查了没拿到"，两者措辞**禁止合并成一句话**，也**禁止把未覆盖写成"无风险 / 正常"**。

### 10.5 禁止事项

- 禁止因为取不到就把该维度整节省略（覆盖范围内的维度）
- 禁止改用训练记忆 / web 搜索编造具体事件
- 禁止把 A 类（返回过大）直接记为"数据缺失"而不拆窄重问
- 禁止把"按用户范围未查询"记成 `NA`，或写成"无风险 / 正常"
- 禁止把 `NOT_COVERED` 与 `NA` 合并成一句话

## 11. ST 股票特殊处理

**场景**：分析对象为 ST/\*ST 股票

**必须执行**：
- **强制六维**：ST/\*ST 标的**不接受专项裁剪**（摘帽、重整、退市判断依赖公告与财务，只看技术面无意义）——即使用户只说"看技术面"，也按六维执行并在报告头部注明锁定原因
- 触发 Step 4 ST 增强分析流程
- 输出 ST 增强模块

**取数补充**：

```
question: 查询{名称}{代码}最近三个月关于重整、重组、退市风险、摘帽的公告
```

**检查方式**：
- 股票名称含 ST/\*ST 标识
- 用户明确提及退市/重整/摘帽

## 错误处理流程图

```
遇到异常
    │
    ├─→ MCP 未连通 → 重试一次 → 仍失败 → 告知用户 + 降级/引导检查连接器
    │
    ├─→ 返回体过大/rich_text超长 → 落盘提取 → 后续查询拆窄（不要按表名拼query）
    │
    ├─→ 字段缺失 → 判断是否合理缺失 → 标注范围 → 降级分析
    │
    ├─→ 区间天数不符 → 改用日行情序列自行计算 N 日涨跌幅
    │
    ├─→ 口径冲突 → 统一复权方式/报告期/时间窗 → 再横比
    │
    ├─→ 新闻/公告/事件取数失败 → 判类型：A 返回过大→拆窄重问(不算缺失) / B 表在但为空→记"未发现" / C 全噪声→剔除后为0才算缺失 / D 真失败→写"未获取到数据"+按 scoring.md §3 记 **NA**（10.4；新闻在专项模式记 `NOT_COVERED`、**不计 NA**）
    │
    └─→ 标的不明 → 要求补充 → 搜索确认 → 继续分析
```

---

## 总结

| 错误类型 | 优先级 | 处理方式 |
| --- | --- | --- |
| 标的不明 | P0 | 用户确认 |
| MCP 未连通 | P0 | 重试一次 → 告知用户 + 降级 |
| 新闻/公告/事件取数失败 | P0 | 先判 A/B/C/D 类型 → A 类拆窄重问（**不算缺失**，豁免于"重试 1 次"）→ D 类写"未获取到数据（原因）"，按 10.4 在评分中记 NA 并标注；新闻在专项模式下记 `NOT_COVERED`（**不计 NA**）；**覆盖范围内维度禁止整节省略**，公告与事件任何模式必跑 |
| 返回体截断/rich_text超长 | P1 | 拆窄查询 / 从落盘文件提取 |
| 数据缺失 | P1 | 降级分析并标注 |
| 区间天数不符 | P1 | 改用日行情序列自算 |
| 复权口径冲突 | P1 | 统一为前复权 |
| 多股口径不一致 | P1 | 锁定同一报告期与时间窗 |
| 研报/舆情噪声 | P2 | 逐条核对并剔除 |
| 信息无法验证 | P2 | 明确标注 |
