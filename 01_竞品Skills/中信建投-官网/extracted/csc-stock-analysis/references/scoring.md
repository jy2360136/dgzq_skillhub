# 多维状态评分规则（唯一定义点）

> **本文件是综合评分口径的唯一定义点**（2026-09 自 `compliance-boundary.md` §5 迁移而来，并吸收产品方法论 v2 的三态处理与覆盖率门槛）。权重、缺失处理、覆盖率、行业适配、版本管理只在此维护；其他文件一律引用本文件，不得复制粘贴或另立标准。
> 分项**阈值细节**的唯一定义点仍在 `technical-analysis-rules.md` §8（本文件引用之）。
> 分数是**规则产物**，不是"我们的评级"：输出时不得附加"高分即值得买"类引导语；判定合规性仍以 `compliance-boundary.md` 三问测试为准。

---

## 1. 定位

评分是对当前数据状态的压缩表达（L1 规则化描述），**不是**收益预测、投资评级或投资优先级。评分不因任何风险规则触发而被人为下调（原"评级联动"已废除；原"风险特征结论"章节亦已于 2026-09-23 删除）。用户显式指定分析维度（**专项模式**）时的评分口径见 **§10**。

## 2. 权重表

| 维度 | 权重 | 满分 | 得分规则出处 |
|---|---:|---:|---|
| 基本面·财务质量 | 0.25 | 25 | `technical-analysis-rules.md` §8.4（六项 0-5 分后归一化到 25） |
| 基本面·估值分位 | 0.15 | 15 | 本文件 §2.1 |
| 技术面·趋势结构 | 0.20 | 20 | `technical-analysis-rules.md` §8.1（强多头 20 / 多头·**弱多头** 15 / 纠缠 10 / 空头·**弱空头** 5 / 强空头 0） |
| 技术面·动量与位置 | 0.15 | 15 | `technical-analysis-rules.md` §8.2（MACD / KDJ·RSI / 布林带各 5 分，含冲突取值规则） |
| 资金面 | 0.15 | 15 | `technical-analysis-rules.md` §8.5（三项各 5 分） |
| 事件与消息面 | 0.10 | 10 | `technical-analysis-rules.md` §8.6（利好/利空量级加权） |

### 2.1 估值分位计分（自 compliance §5 迁入）

PE(TTM) 近三年分位：<30% → 15 分；30%~70% → 线性 8-12 分；>70% → 0-7 分。

**PE 失真场景**（亏损、周期极端利润位、盈利波动过大）：估值维度改记 `NOT_APPLICABLE`（见 §4），PB 分位仅作展示不单独计分（口径风险见 `data-validation.md`）。

## 3. 五态处理（替代原"缺失记 0 分"；2026-09-23 由三态扩为五态）

每个评分单元只能处于以下五种状态之一：

| 状态 | 定义 | 是否计分 | 是否进覆盖率分子 |
|---|---|---|---|
| `SCORED` | 有有效数据且适用 | ✅ | ✅ |
| `NA` | **覆盖范围内**、取数失败或暂未返回 | ❌（该单元权重从总分基数中剔除） | ❌ |
| `NOT_APPLICABLE` | 指标不适用于该行业/标的 | ❌ | ❌ |
| `NOT_COVERED` | **未查询（按用户指定范围外）**——不是数据缺失 | ❌ | ❌ |
| `SAFETY_NET` | 安全网（公告 + 事件）已取数，仅供重大事项提示 | ❌ | ❌ |

> **`NOT_COVERED` 与 `NA` 的区分是硬要求**：前者是"按用户指定范围没查"，后者是"查了没拿到"。报告中措辞分别为 **"未查询（按您指定的范围）"**（只写在头部，不单开章节）与 **"未获取到数据"**（写在对应章节，不写英文状态码），二者**禁止合并成一句话**（否则用户分不清"没查"与"查不到"），也**禁止把 `NOT_COVERED` 写成"无风险 / 无异常 / 正常"**。
> **`SAFETY_NET` 不计分、不进覆盖率分子**：安全网数据属于用户未要求的维度，混进分数会让口径失真；它只服务"已披露重大事项提示"。
> **五态只解决分数层，不解决文字层**（见 SKILL.md 铁律 12）：`NA` / `NOT_COVERED` 在**分数上**不惩罚标的，在**文字结论上**同样不得被引申为负面——禁止"因数据缺失，存在未披露风险""透明度存疑""不确定性较大"类表述。缺失只降低覆盖度与陈述范围，不构成负面事实。分数层的公平与文字层的公平必须同步落地。

### 3.1 防偷懒纪律（NA 的前置门槛，硬性）

**NA 只能发生在"已按 `error-handling.md` 10.4 完成拆窄重问、重问仍失败"之后**：

- 返回体过大被拒 → 必须先拆窄重问（不算缺失，不得直接 NA）
- 表在但值为空 → 记"未发现"，属有效结论，按可用数据处理，**不是 NA**
- 接口真失败 → 重试一次，仍失败才 NA
- 跳过重试直接标 NA 的，按执行不合格处理

> 归一化只改变"缺失怎么计分"，**不改变"怎么取数"**——不因 NA 方案减少任何应做的核验与重试。

### 3.2 总分计算

```text
有效总分 = 已评分子项得分之和 / 已评分子项权重之和
```

得分已是百分制贡献分（财务质量满分 25 = 权重 0.25 × 100，其余同理）。六项齐全、权重之和为 1 时，有效总分等于得分之和。禁止把得分再乘权重，禁止在本式后再乘 100。

算例（分项阈值不变）：

```text
六项齐全：
(16.67 + 15 + 0 + 6 + 10 + 3.33) / 1.00 = 51.00

事件项未评分（权重 0.10 剔除）：
(16.67 + 15 + 0 + 6 + 10) / 0.90 = 52.97

```

**子项粒度**：维度内含子项的（如资金面三项各 5 分、动量三项各 5 分），子项缺失时该子项权重从**维度满分**中剔除，维度得分按可得子项等比归一化；整个维度完全不可得时按整维 NA 处理。

同时必须输出：

- **数据覆盖率**：`SCORED 维度权重之和 / 总权重`（百分比）
- 未评分维度清单（NA / NOT_APPLICABLE / SAFETY_NET 及原因）
- 未覆盖维度清单（`NOT_COVERED`，措辞"未查询（按用户指定范围）"；仅专项模式出现）
- 横向可比性说明（多股对比时）

> ⚠️ **专项模式不适用本节的总分公式**：指定维度子集**不得**归一化到 100（那会造出一个与六维总分不可比的数字），按 §10 只输出分项得分。

## 4. 覆盖率门槛

**只有同时满足以下条件才允许输出总分**：

- 标的和分析日期明确；
- 行情、财务、事件核心数据有效（**"六维均有实质覆盖"这一条仅适用六维模式**；专项模式的覆盖率天然低于本门槛，按 §10 处理，不出总分）；
- 数据覆盖率 ≥ 80%；
- 关键字段报告期与交易日一致；
- 不存在未解决的重大数据冲突（口径冲突未核验前不得计分，见 `data-validation.md`）。

不满足时：**只输出各维度状态标签与数据缺口，不输出总分、不做多股排序**，并说明"覆盖率 X% 低于门槛，本次不给出综合评分"。

## 5. 行业适配

财务质量评分默认使用 §8.4 六项通用阈值（适用于一般制造/消费类）。以下行业须**替换适用指标**，被替换的通用指标记 `NOT_APPLICABLE`：

| 行业 | 替换/增补指标 |
|---|---|
| 银行等金融 | 净息差、不良率、拨备覆盖率、资本充足率、资产质量 |
| 券商 | 经纪/投行/资管收入结构、资本杠杆、自营波动、PB 分位 |
| 周期资源 | 产品价格、现金成本、库存、资本开支、自由现金流 |
| 制造成长 | 收入、订单、毛利率、研发、应收、存货、经营现金流 |
| 医药 | 产品与管线、研发投入、商业化进度、现金消耗、政策风险 |
| 消费 | 销量、价格、渠道库存、品牌与现金流 |
| 公用事业 | 装机/产能、利用率、上网价格、燃料成本、杠杆 |
| TMT | 客户、产品迭代、研发、订单、应收、竞争格局 |

**规则**：

- 替换后的指标无既有固定阈值时，输出各维度**状态标签与缺口**、不给该维度分数（按 NA 处理），并在"未评分项"中注明——**不得临场发明阈值**（临场发明 = L2，违反 L1 三条件）
- 跨行业评分只能用于状态展示，不得据此直接比较不同行业公司的优劣

## 6. 输出格式

```text
综合评分：XX/100（口径：六维固定权重，规则版本 v3.3，见 scoring.md）
有效数据覆盖率：XX%
未评分项：<NA 项及原因 / NOT_APPLICABLE 项及行业依据>（无则写"无"）
```

并逐维列出得分与关键依据数值（对照报告模板第一章表）。

> **专项模式改用 §10 的输出格式**（不出总分），不套用上面三行。

## 7. 多股比较

- 只有**时间、口径、行业适用性、数据覆盖率**一致时才允许展示排序
- 排序必须标注 **"按固定口径评分排序，非投资建议"**
- 覆盖率不一致时，只分别列各自得分与覆盖率，不排序
- **禁止跨口径排序**：专项口径得分**不得**与六维总分放进同一张表排序；专项模式下排序只能在**同一覆盖集合**内进行（逐只口径一致），并标注"专项口径与六维总分不可比"（见 §10.4）
- 分差 ≤ 3 分输出"同级（分差 X 分）"，不强行分胜负

## 10. 专项模式评分口径（适用覆盖范围被用户裁剪的场景）

用户显式指定维度（技术面 / 财报·价值面 / 消息面）时，评分按本节点计算与输出。覆盖范围如何判定见 SKILL.md Step 1。

### 10.1 不出总分（硬规则）

专项模式**不输出 `综合 XX/100`**。

理由：六维权重中大部分天然为空（技术面专项含配套资金面的覆盖率为 0.35 + 0.15 = **50%**）。若强行输出总分，只有两条路——要么因覆盖率不足直接不出分（那"按用户要求来"就等于什么都给不出），要么把子集归一化到 100，后者会造出一个**与六维总分不可比的数字**：用户看到"82/100"几乎必然误读成"这票 82 分"。这与"缺失维度记 0 分系统性压低分数"是同一类坑，只是方向相反。

### 10.2 输出格式

```text
专项得分：<维度名> X / Y（该维度满分）
有效数据覆盖率：XX%
未查询（按您指定的范围）：<维度>
未获取到数据：<项>（原因）（无则不写本行）
不适用：<项>（无则不写本行）
本次只评 <维度>：X / Y。覆盖率 XX%，不足 80%，不出综合评分。
```

> 两份清单**必须分栏**：`NOT_COVERED` 写"未查询（按您指定的范围）"，`NA` 写"未获取到数据"，禁止合并成一句，报告中不写这两个英文状态码。两份清单都只是**覆盖度声明**，**不得据此推出任何负面结论**（铁律 12）。

### 10.3 覆盖率算法

分子分母**仍按六维总权重**计算——**不重算分母、不做子集归一化**。这样专项模式的覆盖率（如技术面专项 = 50%）本身就构成"低于 §4 门槛"的**依据**，不需要另造一套算法。安全网数据记 `SAFETY_NET`，**不进分子**。

### 10.4 排序与对比

- 专项得分**禁止**与六维总分放进同一张表排序
- 专项模式下多股排序仅限**同一覆盖集合内**（逐只口径一致），标注 `按固定口径评分排序（专项口径：仅技术面），非投资建议`
- 与六维总分并列呈现时只可对照，不得排序

### 10.5 与 §3 / §4 的关系

本节是 §3 五态 + §4 门槛在"覆盖范围被用户裁剪"场景下的适用说明，**不改变** §2 权重、§5 行业适配、§7 多股比较、§8 版本纪律。
